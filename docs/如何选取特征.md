# 如何选取特征

本文只写 **Session 剩余返回时间 τ** 模型的特征选取过程，不写实验数字。候选字段以 [`模型输入特征统计.md`](模型输入特征统计.md) 为准。分组定义在 `scripts/python/pipeline_inventory_groups.py`。

## 1. 要选什么、不能选什么

第一层模型估计的是：一个已经出现过的 Session，从当前请求结束时刻起，还要多久才会以**消息前缀严格增长**的方式再回来。输出是标量时间 τ（秒）。

硬约束：

- 只用清单里已经存在的原生字段，不发明旋钮，也不做 `n_children`、age、TTFT 这类加工。
- 标签用原始 GLM 日志的 `start_time`。重放墙上的时钟、`time_stats`、节点 `last_access_time` 只作为原生字段进 dump，**不能当 τ 的标签或替代时钟**。
- 资源池 / 调度队列在清单里标成控制器专用；选取流程仍把它们收进槽位并单独成组，用同一套 permutation / ablation 验证，而不是事先删掉。
- `sampling.max_new_tokens` 在重放里等于日志里的 completion 长度，不是线上 `client.max_tokens`。它单独成组 `leaky_replay_cap`，**不进官方全模型**。

## 2. 总流程

```text
清单原生字段
    → Session 标签 + 时间切分
    → LRU 采集（关 HiCache）+ 压缩重放
    → request_end dump 与标签按 rid 对齐
    → 169 槽位编码
    → 16 组覆盖校验
    → 官方 168 列 LightGBM（δ=1）
    → 组 permutation（同组同行打乱，40 次）
    → 组 ablation（删整组重训）
    → 单列 permutation（含义 / 来源 / 组）
    → 组结论与单列目录对照
```

冻结仍要求：在**完整时间切分**上做分组验证集 ΔNLL。嵌套 small 的 val/test 只用来跑通流程，不是官方 fold。

## 3. Session 与标签

数据：`third_party/glm-5dot1_onlinedata/glm-5dot1_onlinedata_lt32k.jsonl`。脚本：`scripts/python/split_glm_session_return.py`。

Session 不是 SGLang 原生 Session 对象。一条 Session 由「第一条 user 消息的 hash」圈定；同一 Session 内，后一条请求的 `messages` hash 序列必须是前一条的**严格前缀延长**，才算续上。

对每条请求：

- 若在观察窗结束前出现下一次续上：`δ = 1`，`τ` = 两次原始 `start_time` 之差（秒）。
- 否则右删失：`δ = 0`，`τ` = 从该请求 `start_time` 到本切分窗口右端的时间。窗内未见的续上不得跨窗借用。

全量切分：全部请求按 `start_time` 排序，70% / 15% / 15% 划 train / val / test。small 切分：取时间轴上最前 `--small-n`（默认 2200）条，用同一比例再切一刀。small 的 train→val→test 嵌在官方 train 时间前缀里。

## 4. 采集

服务：`scripts/shell/glm51_session_return_node0.sh` + `glm51_session_return_node1.sh`。Radix 用 LRU，关 HiCache。`PYTHONPATH` 挂上 `scripts/python/session_return_dump`，`SESSION_RETURN_DUMP_DIR` 指向本次 run 的 `server_dump/`。

Hook 在请求结束时写一条 `event = request_end` 的 JSONL，字段对应清单 §1–7，不做聚合。客户端压缩重放 `scripts/python/replay_glm_session_return.py`：按 small 切分的到达顺序发请求，去掉空闲 gap，生成长度 cap 到日志 completion。标签仍在 split 行上，不看重放墙钟。

对齐：客户端 `trace_id` = dump `rid`。只保留 dump 里有 `request_end`、且 split 行带 `small_split` / `tau_s_small` / `delta_small` 的请求。

## 5. 槽位怎么变成模型输入

`scripts/python/rank_inventory_permutation.py` 的 `SPECS` 把清单展开成 **169** 列。LightGBM 只能吃标量，因此：

| kind | 做法 |
|---|---|
| `num` / `bool` | 原值；缺失为 NaN |
| `len` | 序列 / 列表 / 字符串取长度 |
| `present` | 对象有/无 → 1/0 |
| `cat` | 字符串；在 **train** 上 factorize，val/test 未见记 −1 |
| `effort` | reasoning_effort 序数 |

`client.*` 来自重放保存的原始请求体，其余来自 `request_end` dump。类别编码不得用 val/test 拟合。

## 6. 分组

16 组必须恰好覆盖 169 列：无遗漏、无组间重复、无组外多余。`validate_groups()` 在跑 permutation 前检查，失败即停。

组内应是同一语义、打乱时一起破坏的字段。高度共线的长度（例如 `fill_len` 与 `cache_protected_len` / KV 长度）放进同一组，避免单列 permutation 把份额拆碎。

| 组 | 收什么 |
|---|---|
| `leaky_replay_cap` | `sampling.max_new_tokens`（重放 completion cap） |
| `output_len` | 本请求实际输出长度 / 结束原因：`req.finished_len`、`req.output_ids`、`req.finished_reason`、`req.to_finish` |
| `prompt_occupied` | 占用 KV / prompt 长度（含 last_node 的 token 序列长度） |
| `this_turn_prefill` | `req.extend_input_len` |
| `cache_hit` | 各层前缀命中计数 |
| `client_sampling` | 客户端 + 调度器副本的采样旋钮（不含泄漏 cap） |
| `sampling_stop_penalty` | 停止条件与重复惩罚 |
| `request_content` | 请求体、工具、stream 标记（序列取长度） |
| `reasoning` | 本请求 reasoning 状态 |
| `multimodal` | 图像 / 音频 / 视频及容器是否存在 |
| `identity` | ID、extra_key、LoRA、routing、priority |
| `container_flags` | sampling_params 对象是否存在 |
| `replay_time` | 重放时钟时间戳 |
| `native_session` | 原生 SGLang Session 对象（Chat 路径上通常缺失） |
| `radix_node` | last_node 结构、锁、LRU 指针（不含 token 长度） |
| `resource_pool` | KV 分配器快照与调度队列长度 |

成员列表以 `GROUPS` 为准，改组后必须重新跑覆盖校验。

## 7. 模型与评价协议

代理模型：LightGBM 回归，`scripts/python/train_session_return_lgbm.py` 的 `fit_lgbm`。只在 **δ=1** 上训练和算 MAE / RMSE / R²。删失行的 τ 是到窗口右端的时间，不能和观测返回时间混在一起比误差。

- 用 train（δ=1）拟合，val（δ=1）做 early stopping。
- test（δ=1）是嵌套 holdout，不参与选轮数。
- 对照：用 train 观测 τ 的均值当常数预测。

两套全模型：

- **官方全模型**：168 列，去掉 `sampling.max_new_tokens`。其它组的 permutation / ablation 都在这套上做，避免泄漏列代替 `finished_len` / `output_ids`。
- **含泄漏模型**：169 列。只用来给 `leaky_replay_cap` 打 permutation，以及把它的 ablation 定义成「168 列 vs 169 列」。

## 8. 组 permutation

脚本：`scripts/python/pipeline_inventory_groups.py`。

对已经训好的全模型，在 val / test 的 δ=1 子集上：

1. 记下未打乱 MAE。
2. 把该组在矩阵里的列，用**同一行置换**一起打乱（组内相对关系还在，与 τ 的对应被切断）。
3. 再预测，得到 ΔMAE = MAE(打乱) − MAE(原序)。
4. 独立重复 40 次，报均值、标准差、5%/95% 分位、ΔMAE>0 的比例。

正的 ΔMAE 表示模型用过这组信息。接近 0 可能是：组内全常数 / 全缺失、树没用这些列、或信息已被其它组完全代替。

## 9. 组 ablation

同一脚本，每组再做一次 **删整组后重训**：

- 非泄漏组：从 168 列里去掉该组成员，用同一套 `fit_lgbm` 重训，ΔMAE = MAE_without − MAE_all。
- 泄漏组：比较 168 列官方模型与 169 列含泄漏模型，不再另训第三份。

Permutation 问的是「当前这棵树还在不在用这组」；ablation 问的是「没有这组、允许重学分担之后，误差还变不变大」。两者都大、且 test 同号，才把该组当成可靠信号。只在 val 上 ablation 变大、test 翻号的，当作嵌套 small 噪声，不冻结。

## 10. 单列 permutation

组结论之后，再对 169 列逐列打乱，便于看组内谁在贡献。脚本：`scripts/python/catalog_inventory_importance.py`。

- 168 个非泄漏列：在官方模型上各打乱 40 次。
- `sampling.max_new_tokens`：在 169 列模型上打乱，并标明不属于官方模型。
- 每列附带：含义、来源（按 dump 前缀：客户端请求 / 分词 / 调度器 Req / sampling_params / time_stats / Session / Radix last_node / KV 分配器 / 调度器队列）、所属组、编码类型、train 取值数。
- 按 val ΔMAE 降序。共线列会把份额拆开，单列排名必须和组结论一起读，不能单独拿来删列。

## 11. 怎么读、何时冻结

读的顺序是 **组 → 单列**，不是反过来。

1. 组 permutation 与组 ablation 都明显、test 同向 → 组保留。
2. 组 permutation 很大、ablation 重训后几乎收回 → 当前树在用，但可被其余列代替；泄漏 cap 按这条处理，官方模型不收。
3. 组 permutation ≈ 0、ablation 也 ≈ 0 → 本切分上无信息（常数、缺失、或与 τ 无关）。
4. 单列目录用来解释组内结构，以及标出含义 / 来源；不根据某一列的 ΔMAE 单独冻结。

嵌套 small 的 val 用了 early stopping，不能当官方验证。特征冻结要在完整时间切分上，对保留组做验证集分组 ΔNLL（或与之等价的删组重训），通过后再冻输入，不再改槽位。

## 12. 组内留哪一列

组已经重要之后，组内再按质量挑代表，不要按单列 ΔMAE 拆开共线列。

过滤：泄漏 cap、重放时钟、请求 ID / 节点指针、Chat 上常缺失的原生 Session、常数列。高基数的长度计数不是 ID，不能按「取值数 ≈ 行数」丢掉。

组内 `|ρ| ≥ 0.99` 的列收成一团，只留一个。组间 `|ρ| ≥ 0.95` 视为同一份信息，梯子上只留先选中的那个。团内打破并列的顺序：

1. 缺失最少（train 上 NaN 比例）
2. 语义稳定（不是运行时指针、不是重放时间戳）
3. 线上最好拿：API 原值 > request_end 调度器标量 > 对已有序列取长度 > 解引用 `last_node` > 分配器快照
4. 延迟最低：已有标量 O(1) 优于 `len(list)`，优于走 Radix
5. 与其它组的 `|ρ|` 最低

资源池 / 调度队列按清单位于控制器，不进 τ 模型的核心维；只有在核心代表不够填预算时才标成「控制器快照」往后排。

组内再做组合消融：其余官方 168 列保持不变，只换该组的子集（空 / 单代表 / 代表+辅助 / 共线两列都留）。共线两列都留应当不优于只留质量更好的那一列。用 val 选组合、用 test 看是否同向；nested small 上 test 变差的组合不升级成冻结。

嵌套预算 `k ∈ {8,12,16,20,24}` 按「组可靠程度 → 组内代表 → 跳过 ρ≥0.95 副本」往上加，必须 `8 ⊂ 12 ⊂ 16`。凑不够的维数不得用 ρ=1 的副本或泄漏 cap 去填；写明缺维，而不是假凑。
