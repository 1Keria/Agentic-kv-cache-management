# KV 续上概率：控制器

模型只出 `{p_i(H_k)}`。本文规定控制器怎么用这份分：何时驱逐、哪些硬锁、怎么把各档合成 `π`、怎么计价、按什么顺序扔。分工与标签见 [`系统设计.md`](系统设计.md)；

换打分器不改本文。水位、容量、这次要腾多少页不进模型。

## 1. 一次驱逐

时机与 LRU 相同：allocator 发现空闲页不够，调用 `evict()`。训练不在这次里做。

```text
1. 这次要腾多少页
2. 硬锁：：正在运行的请求路径，以及当前正在进行调度准入检查的等待请求前缀。
   候选为空：不调用模型；新请求继续等
   decode 自己都不够：抢占在跑请求，不扔锁住的前缀
3. 模型对可驱逐叶子打 {p_i(H_k)}
4. 控制器合成计价概率 π、计价、得到 NetValue
5. Full 圈按 NetValue 从低到高扔叶子；V4 的 SWA 圈见第 6 节
   够这次的页数就停
```

若关键路径太重，一次 `evict()` 只对当时可驱逐叶子打一次分，按净价值入堆再扔；只有删叶子后新晋升出来的父节点才补打。不改「腾页时才需要一份分」。

## 2. 硬规则

确定会发生的未来不交给模型：

- 正在跑的请求路径：锁住
- 等待队列已经要点的前缀：锁住
- 其余叶子：可驱逐，由第 4–5 步排序

硬锁不是「Agent 优先」或 `session_alive` 保命。活着但暂时没人用的前缀，仍按净价值排。

## 3. 合成 `π`：用满所有档，权重加在增量上

`p_i(H_k)` 是嵌套的窗内命中概率：`H_1 < H_2 < ⋯ < H_K`，校准好时应有 `p_i(H_1) ≤ ⋯ ≤ p_i(H_K)`。短窗命中已经包含在长窗里。控制器合成一个计价标量 `π_i`，**每一档都进 `π`，不选一档丢掉其余。**


也不要把 `{p_i(H_k)}` 当三个独立分数再写 `π = Σ w_k p_i(H_k)`。嵌套 CDF 上加大长窗的 `w`，摊到增量上其实是**短窗质量更重**。例如 `w = (0.2, 0.3, 0.5)`：

```text
π = 0.2 p(H1) + 0.3 p(H2) + 0.5 p(H3)
  = 1.0 Δp1 + 0.8 Δp2 + 0.5 Δp3
```


```text
Δp_{i,1} = p_i(H_1)
Δp_{i,k} = max(0, p_i(H_k) − p_i(H_{k-1}))    k = 2..K

π_i = Σ_k α_k Δp_{i,k}
```

`α_k` 日内固定，不临场生成新的 `H`。约束：

```text
所有 α_k > 0          # 没有一档被丢掉
α 单调不增            # 同样会 match，来得早的略更值钱
禁止任何 α_k = 0      # 包括「占用高就把长档权重打成 0」
```

`α_k = 1` 时 `π_i = p_i(H_K)`：三档的命中质量都算进去了，但 CDF 的形状（马上回来 vs 几分钟后回来）用不上。要吃形状，`α` 必须有差别；要避免再塌成最短窗，长档的 `α` 不能到 0。

第一版用轻度衰减。当前三档约 **30s / 198s / 2371s**（训练集非截尾 `T_i` 的 0.95 / 0.96 / 0.99 分位）：

```text
α = (1.0, 0.7, 0.5)
```

含义：30 秒内会 match 的质量全额计入；落在 (30s, 198s] 的打七折；(198s, 2371s] 的打五折。死尾巴三档 Δp 都接近 0；马上续上的 Δp1 大；tool-wait 后几分钟才回来的 Δp1 小、后面 Δp 仍能把 `π` 抬起来。对照实验保留 `α = (1, 1, 1)`（即只用最长窗的累计 `p`），看形状项有没有额外收益。

松/紧若以后还要进合成，只允许**轻微倾斜** `α`（例如把 (1.0, 0.7, 0.5) 收到 (1.0, 0.85, 0.7)），依据是这次要腾多少页或队列还在等什么，而不是对一个恒接近 1 的占用做表查，更不能把后档打掉。


## 4. 计价：`λ` 是门槛，不是占用

本段 token 与该叶占用的 KV 同量纲时：

```text
NetValue_i = (π_i − λ) × KVSize_i
```
同一次驱逐里所有候选共用一个 `λ`。

```text
π < λ：越大越该扔（先腾低概率的大尾巴）
π > λ：越大越该留（长且还会用的前缀留下）
```

`λ` 日内固定，取远小于 1 的常数（建议 0.05～0.1）。**不要**再写成 `λ = λ0 × 占用`。占用在 `evict()` 里接近 1 时，活叶子 `π≈1` 会把净价值打到 0 附近，排序失效。

水位若还要参与，只允许把 `λ` 在小区间里微调（例如 0.05↔0.15），禁止拉到 1。

接入时先允许 `λ = 0`：排序退化为 `π × KVSize`。用来确认 victim 已经离开 LRU，再加回小 `λ` 看体积项有没有额外收益。

驱逐释放的是这一叶的页，`KVSize_i` 用本节点占用，不用 root 到此的路径 token。路径长度只进模型特征，不进 HoldCost。

## 5. 排序与破并列

```text
先扔 NetValue 最低的
并列：先扔 π 更低的
再并列：先扔 KVSize 更大的
不要用 last_access_time
```

`last_access_time` 只在打分失败或没有 `π` 时作兜底。净价值一挤平，第二键若是访问时间，控制器就是 LRU。

## 6. SWA 墓碑（V4）

SWA 要腾的是窗槽。候选经常是内部节点：儿子还在，节点不能删，动作是 `free_swa` + 打墓碑。Full / 压缩可以还在。网络仍然只给叶子打 `{p_i(H_k)}`；内部节点的 `π` = 下游可驱逐叶子 `π` 的 max（挖这个窗会伤到的最值钱叶子）。

匹配：从根往叶子走，碰到墓碑就重新数后面还活着的 SWA。这段 **≥ sliding_window_size**（V4 为 128）才能把命中报到墓碑之后；不够则 `cached_tokens` 截在墓碑前。

SWA 圈每一刀重选，排序：

```text
先扔 π 更低的
并列：先扔离根更近的
再并列：NetValue 更低的、或 KVSize 更大的
不要用 last_access_time
```

同一条链上这就是从上往下挖。不要在控制器里加「末 128 不许动」或 Agent 保命。

oh6 上试过把「打墓碑后已经能报的命中会变短」做成 π 之后的第二键：全局 TW 从 0.531 掉到 0.396。原因不是思想本身有 13 个点的空间，而是内部节点的「会变短」取了**所有**下游叶子的 max——一条短的、低 π 的旁支会把父节点标成会变短，排序就跳过它去挖高 π 那条链的中间。serving 仍用上面的 π → 离根近。若再试，只应按给出 `π` 的那片叶子（max-π）算会不会变短。

## 7. 验证

改的是控制器，先看驱逐序，再看 serving。

1. 影子或一次 `evict()`：MLP victim 与 LRU victim 的重合率。仍接近 100% → `{p_i(H_k)}` 校准或 `H_k` 太短，不是 `λ` 没调完。
2. 重合明显下降后再跑一截 mix（不要一改完就打满 3h），看 TW hit、各类命中 token。
3. `λ = 0` 与 `λ ∈ [0.05, 0.1]` 对照：体积项是否额外有用。

不要为了赢 LRU 在控制器里加 `session_alive` / Agent 保命硬规则，那是把打分器旁路掉。

## 8. 控制器改不了的

- 模型权重、特征、`H_k` 边界：按日重统计、日内冻结，见系统设计。
- 比现有最长档（约 40 分钟）更长的复用：需要再定 `H_k` 和重训，不是把 `λ` 再乘占用能补上的。
- 几乎没有再次使用时（单跳、无共享前缀），各档 `p` 接近 0，高压下接近按大小驱逐。这是该有的行为。

## 9. 动态参数提案（待审核，尚未实现）

本提案保留第 1～8 节已经验证过的控制器和 Full/SWA 驱逐流程，只把固定的 `α`、`λ` 改为随系统压力变化的运行时参数。模型、候选集合、节点级驱逐动作和排序结构均不改。

```text
Δp_{i,1} = p_i(H_1)
Δp_{i,k} = max(0, p_i(H_k) − p_i(H_{k-1}))

π_i(t) = Σ_k α_k(t) Δp_{i,k}
NetValue_i(t) = (π_i(t) − λ(t)) × KVSize_i
```

Full 与 SWA 使用同一套参数生成规则。二者底层释放动作不同，但不分别设计 α、λ，也不增加新的动作损失公式。

### 9.1 两种压力时间尺度

控制器不直接使用接近恒为 1 的瞬时 occupancy，而是使用两个实际可测信号：

```text
慢压力：TurnoverTime = CacheCapacity / EMA(NewKVPagesPerSecond)
快压力：本次必须释放页数 Q / 当前可驱逐页数 E
```

- `TurnoverTime` 表示按近期写入速度，整个缓存大约多久被新 KV 周转一遍，用于调整时间档权重 `α`；
- `Q/E` 表示当前这次驱逐需要从候选中拿走多大比例，用于确定概率门槛 `λ`。

一次 `evict()` 内冻结 `α` 和 `λ`。下一次 `evict()` 可以使用更新后的值。

### 9.2 动态 `α`：根据周转时间选择有效预测范围

当前模型 horizon 为：

```text
H = (30s, 198s, 2371s)
```

设当前 `TurnoverTime=T_c`。若 `T_c` 落在 `H_m` 与 `H_{m+1}` 之间，则：

```text
α_k = 1                                      k ≤ m
α_{m+1} = (T_c − H_m) / (H_{m+1} − H_m)
α_k = 0                                      k > m+1
```

边界处理：

```text
T_c ≤ H_1：α = (1, 0, 0)
T_c ≥ H_K：α = (1, 1, ..., 1)
```

三档示例：

```text
T_c = 100s
w = (100 − 30) / (198 − 30)
α = (1, w, 0)
π = p(H_1) + w × [p(H_2) − p(H_1)]
```

因此参数变化由系统测量值唯一确定：

- 周转慢：更多远期概率质量进入 `π`；
- 周转快：只保留近期概率质量；
- 不再人工指定 `(1,0.7,0.5)`。

当 `T_c<H_1` 时，现有模型无法分辨 30 秒以内更细的时间差，只能饱和到第一档。如果这种状态经常出现，应增加更短 horizon 并重新训练，不能在控制器里猜测。

### 9.3 动态 `λ`：根据本次释放需求选择概率门槛

先使用动态 `α` 得到所有候选的 `π_i`。将候选按 `π_i` 从低到高排列，并按节点 `KVSize_i` 累加：

```text
λ = 最小的 π 阈值，使：

Σ_{i: π_i ≤ λ} KVSize_i ≥ Q
```

也就是以 `KVSize` 为权重，在候选概率分布上取 `Q/E` 对应的加权分位点。

- `Q/E` 小：`λ` 靠近最低概率，只明显推动少量低价值候选；
- `Q/E` 大：`λ` 上升，更多候选落入 `π_i<λ` 区域；
- 同一次 `evict()` 只计算一次 `λ`，避免逐节点振荡。

`λ` 仍沿用原公式的含义：它不直接决定释放多少页，而是改变不同大小节点的相对排序。若候选节点大小完全相同，减去共同的 `λ` 不改变顺序，这是预期行为。

### 9.4 Full 与 SWA 的使用方式

两者共用：

```text
同一个 MLP 输出
同一个 TurnoverTime → α 规则
同一个 Q/E → λ 规则
同一个 π 与 NetValue 定义
```

实现保持现状：

- Full 仍按 `NetValue → π → KVSize` 选叶子；
- SWA 仍按 `π → prefix_depth → NetValue → KVSize` 选墓碑节点，并在每刀后重选候选。

因此动态 `α` 会直接影响 Full 和 SWA；动态 `λ` 主要影响 Full，在 SWA 中通常只负责后置破并列。若后续要求 `λ` 成为 SWA 主排序因素，就必须修改 SWA 排序结构，不属于本次“只改参数”的范围。

### 9.5 在线状态与更新

第一版采用以下操作规则：

1. 分别统计当前被驱逐资源的 capacity、写入页数和可驱逐页数，但使用完全相同的参数生成算法；
2. `NewKVPagesPerSecond` 使用 60 秒采样窗口和 5 个窗口半衰期的 EMA；
3. α 每 60 秒最多更新一次；相邻两次 `TurnoverTime` 变化不足 10% 时保持不变；
4. λ 在每次 `evict()` 开始时根据当次候选和 `Q` 计算，并在本次调用内冻结；
5. 冷启动未形成 EMA 前使用 `α=(1,1,1)`；候选不足或模型失败时退回现有 LRU；
6. 日志记录 `Q/E、write_rate、TurnoverTime、α、λ` 及最终 victim。

### 9.6 实现与验证顺序

审核通过后按以下顺序实现，避免同时改变两个变量：

1. 只增加压力统计和日志，不改变现有 victim；
2. 固定 `λ=0.05`，只接动态 α，先跑单测和短重放；
3. 固定通过验证的 α，再接动态 λ；
4. 最后同时启用动态 α、λ，运行完整 workload；
5. 分别对照固定 `(α,λ)`、仅动态 α、仅动态 λ、两者动态。

需要报告全局及 Request/OH 分组 token-weighted hit、重算 token、TTFT，以及 scorer 和 eviction wall time。若动态 λ 对 SWA victim 几乎无影响，应如实报告，而不是把它描述成 SWA 的核心参数。

## 附录 A. 已否决的动作级 V2 草案

第 1～8 节描述当前实现及其历史设计。当前实验脚本实际使用 `α=(1,1,1)`、`λ=0.05`：此时 `π_i=p_i(H_K)`，前两档不影响 serving 排序；SWA 中 `λ` 通常只在 `π` 和深度都相同时才生效。

以下方案因引入额外的动作损失建模而被否决，仅保留为讨论记录，不进入当前实现计划。

V2 不再先造一个节点分数再分别解释 Full/SWA，而是直接回答：

> 为腾出所需 KV 页，下一步执行哪个动作，造成的单位释放页预期复用损失最小？

设驱逐动作 `a` 释放 `M_a` 页，导致未来可命中 token 减少 `Δh_{a,j}`，其中 `j` 是受动作影响的叶子：

```text
Loss(a)    = Σ_j U_j × Δh_{a,j}
Density(a) = Loss(a) / M_a
```

控制器按 `Density(a)` 从低到高执行动作，直到释放页数达到本次目标。各项含义为：

```text
U_j          叶子 j 未来复用的时间折扣概率
Δh_{a,j}     动作真正造成的可命中 token 损失
M_a          动作真正释放的物理页
Density(a)   每释放一页付出的预期命中 token
```

第一版用 token 数近似重算成本；如果后续有稳定的 prefill cost profile，只把 `Δh` 换成预计 prefill 时间，控制流程不变。

### A.1 多时间窗与 `K` 的选择

令 `T_j` 为叶子 `j` 下一次复用的间隔。模型输出离散累计分布：

```text
p_j(H_k)   = P(T_j ≤ H_k)
Δp_{j,1}   = p_j(H_1)
Δp_{j,k}   = max(0, p_j(H_k) − p_j(H_{k-1}))，k≥2
```

`Δp_{j,k}` 是下一次复用落在第 `k` 个时间区间的概率质量。控制器使用整个离散时间分布，不把多个输出当作互相独立的分类概率。

当前 checkpoint 的 `K=3`，边界约为 30s / 198s / 2371s，但论文不能把“三档”写成先验。下一版按以下流程选取，且所有选择只看训练集和验证集：

1. 在训练集统计未截尾复用间隔 `log(1+T)` 的分布；截尾样本只训练仍可确定的 horizon，未知标签 mask 掉。
2. 候选 `K∈{1,3,5,8}`；每个 `K` 的候选边界由训练集复用间隔分位点生成，并在训练前冻结。
3. 所有候选使用相同特征、训练预算和随机种子集合。
4. 在验证集同时报告各 horizon 的 Brier/ECE、最终 `Density` 排序产生的 token-weighted hit，以及 scorer 延迟。
5. 选择“下游收益—校准—开销”曲线的最小拐点；只有三档处于拐点时，论文才采用 `K=3`。

因此，“为什么不是更细的时间段”由消融回答：更细的网格只有显著改善校准或下游命中时，才值得承担更稀疏的区间标签和更高推理开销。

### A.2 `α`：规则固定，数值随资源周转缓慢变化

V2 不人工写死三个互不相关的数。人只定义时间价值函数：

```text

d(t; τ_r) = exp(−t / τ_r)
```

当前要释放的资源 `r` 的特征周转时间定义为：

```text
τ_r(t) = Capacity_r / EMA(NewKVPagesPerSecond_r)
```

容量和写入速率都以页计数，因此 `τ_r` 的单位是秒。这里的下标 `r` 只表示本次动作释放哪一种底层资源，不表示存在两套策略：Full 与 SWA 使用同一条 `Capacity/WriteRate` 更新规则和同一组时间价值公式，不允许分别手调两套 α。训练集为每个时间区间保存代表复用时间 `m_k`，优先取该区间未截尾样本的中位数。运行时生成：

```text
α_{r,k}(t) = exp(−m_k / τ_r(t))
U_{r,j}(t) = Σ_k α_{r,k}(t) × Δp_{j,k}
```

解释如下：

- 写入快或容量小：`τ_r` 变小，远期复用的机会成本更高，后档权重下降；
- 写入慢或容量大：`τ_r` 变大，各档权重趋近 1，允许保留更长期的复用；
- `α=(1,…,1)` 是无时间折扣基线，此时 `U_j=p_j(H_K)`。

### 11.1 在线更新操作

初版规则如下，具体数值需要做敏感性实验：

1. 按资源池累计新写入页，不用瞬时 occupancy 直接查表；
2. 默认控制周期为 60s，写入速率 EMA 的半衰期为 5 个周期；
3. 将 `τ_r` 限制在 `[H_1, 4H_K]`，无写入时取上界；
4. 每个控制周期最多发布一次新 `α_r`，一次 `evict()` 内保持不变；
5. 记录每次发布的 `write_rate_r / τ_r / α_r`，保证实验可复现；
6. 冷启动收满两个周期前，使用离线训练 workload 的 `τ_r` 中位数。

这是慢速资源适配，不是“占用一高就立即把长档打成 0”。所有 `α_{r,k}` 始终为正，并随 `k` 单调不增。

### A.3 统一动作级控制器与两种动作适配器

统一控制循环如下：

```text
1. allocator 给出本次需要释放的资源类型 r 和页数 Q
2. Full/SWA 动作适配器枚举合法动作，并为每个动作返回 (M_a, {Δh_{a,j}})
3. 统一控制器用同一模型输出和同一动态参数计算 Loss(a) / Density(a)
4. 执行 Density 最低的动作
5. 更新受影响的候选；未释放够 Q 页则回到第 2 步
```

策略只存在于第 3～4 步。第 2、5 步因底层动作语义不同而有两种实现，但不能各自增加独立的优先级公式、流量偏置或手调参数。

#### A.3.1 Full 动作适配器

一个 Full 动作是删除当前可驱逐叶子的 Full KV：

```text
M_a       = 该动作实际释放的 Full 页
Δh_{a,j}  = 删除前后叶子 j 可匹配 Full token 的差值
Loss(a)   = U_j(r) × Δh_{a,j}
```

第一版叶子动作通常只影响该叶子。删除后如果父节点新晋升为可驱逐叶子，将父节点作为新动作重新计算并入堆。先比较 `Density`；数值并列时先选 `M_a` 更大的动作以减少动作次数，再用稳定 node id 破并列。`last_access_time` 只在模型失败时兜底。

#### A.3.2 SWA 墓碑动作适配器

一个 SWA 动作是对候选节点执行 `free_swa` 并打墓碑。它可能同时改变多个下游叶子的可报告匹配长度。对每个受影响叶子 `j`：

```text
L_before(j)  = 当前规则下可报告的 cached_tokens
L_after(a,j) = 模拟执行动作 a 后可报告的 cached_tokens
Δh_{a,j}     = max(0, L_before(j) − L_after(a,j))

M_a          = 动作实际释放的 SWA 页
Loss(a)      = Σ_j U_j(r) × Δh_{a,j}
Density(a)   = Loss(a) / M_a
```

`L_after` 必须复用真实匹配语义：墓碑之后连续活 SWA 达到 `sliding_window_size` 才能继续报告，不能用节点长度或路径深度近似。多个叶子的期望损失可以线性相加；共享节点被多条未来请求复用时，本来就可能节省多次 prefill。

SWA 每执行一个动作后重新选择，因为上一刀会改变 `L_before`、候选集合和后续动作的边际损失。同密度时先选释放页更多者，再选离根更近者，最后用稳定 node id 破并列。深度只用于确定性破并列，不再压过真实边际损失。

#### A.3.3 与失败版本的区别

oh6 上曾把 `hit_lost` 布尔量放在 `π` 后作为第二键，全局 TW 从 0.531 降到 0.396。那个版本有两处归因问题：

1. 用所有下游叶子的最大命中缩短标记候选，却用另一个 max-π 代表候选价值；
2. 只判断“是否缩短”，没有计算缩短多少，也没有除以实际释放页。

V2 对同一个 `(动作, 叶子)` 同时计算 `U_j` 与 `Δh_{a,j}`，再形成单位释放页损失，因此不是恢复原来的布尔排序。实现前必须先用手工小树验证 `L_before/L_after`，不能直接跑长 workload。

### A.4 `λ` 的位置

V2 的强制驱逐排序不再使用：

```text
NetValue = (π − λ) × KVSize
```

allocator 已经给定本次必须释放的页数，动作间应比较“每释放一页损失多少”。固定 `λ` 对所有动作施加相同单位页价格，不提供额外的边际排序信息。

如果以后加入 admission/bypass，`λ_r` 可以作为资源池影子价格：

```text
Admit(a) iff ExpectedBenefit(a) / M_a > λ_r
```

但 admission 与本次 victim 选择是两个问题。V2 第一版先删除驱逐路径中的 `λ`，不同时引入 admission。

### A.5 原草案的实现顺序

1. **只加观测**：统计 Full/SWA capacity、新写页速率和 `τ_r`，不改变 victim；
2. **离线单测**：构造直链、分叉、墓碑后 `<128 / =128 / >128` 的小树，核对每个动作的 `M_a`、`L_before/L_after` 和 `Density`；
3. **固定 α 接统一控制器**：先以 `α=(1,1,1)` 接动作级排序，Full/SWA 只实现各自动作适配器，隔离动作计价本身；
4. **影子模式**：同时打印 LRU、当前 MLP、V2 victim 及各字段，不执行 V2；
5. **短重放**：先跑 workload 小切片，检查 victim 序列、实际释放页和命中变化；
6. **动态 α**：固定控制器后再接 `τ_r→α_r`，避免同时改变两个变量；
7. **完整重放**：短实验方向正确后再跑完整 oh6。

任何阶段如果 SWA 的 `L_after` 与真实下一次 match 不一致，应停止 serving 实验并先修语义单测。

### A.6 原草案的验证与论文消融

至少独立报告：

1. 时间网格：`K=1/3/5/8`；
2. 权重：全 1、离线固定 `τ`、在线动态 `τ_r`；
3. 控制器：当前 `NetValue`、只按 `U`、动作级 `Loss/M`；
4. 动作适配器：Full 的直接匹配损失与 SWA 的精确墓碑 `Δh`；
5. SWA：当前 `π→depth` 与统一控制器下的精确 `Δh`；
6. 开销：scorer、Full/SWA 动作模拟、每刀重选分别占总 eviction 时间的比例。

主指标报告全局及 Request/OH 分组的 token-weighted hit、重算 token、TTFT，不能只报总体命中。所有动态状态随运行日志落盘，使同一到达序列可以复核控制器决策。

部署顺序固定为：语义单测 → 影子 victim → 短重放 → 完整重放。不要为了赢 LRU 加 `session_alive` / Agent 保命硬规则；这些信号只能通过训练好的复用概率进入动作效用。

### A.7 原草案仍然改不了的部分

- 模型特征、概率校准及 horizon 之外的复用；如果 `p(H_k)` 不准，动作公式不能补救；
- 错误的 session 生命周期信号；例如结束后仍长期标为 alive，会先污染模型输出；
- 实际匹配语义计算错误；特别是 SWA 墓碑之后的连续活窗；
- 几乎不会再次使用的单跳私有前缀，其 `U` 应接近 0，高压下优先释放是预期行为。
