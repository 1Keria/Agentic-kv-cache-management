## 1. 要证明什么（负载必须服务这句话）

> 在「长程 agent、轮间有空档、多 Session 抢 KV」时，  
> 保住还会再用的 Session / 入口前缀，比纯 LRU 更划算；  
> 且保留成本可控。

因此负载要同时具备：

1. **真前缀**（可 radix / LCP）  
2. **真 Session 内间隙**（工具/人思考带来的空档）  
3. **可控的跨 Session 交错**（把 cache 打到会淘汰）

缺 3 → 测不出相对 LRU 的差异；用假前缀凑 1 → 机制证据不硬。

---

## 2. 核心原则：Session 内真，Session 间显式合成

| 层 | 来源 | 是否合成 | 说明 |
|---|---|---|---|
| **内容（prompt / messages）** | 自有 `lmcache_traces`（OpenHands / SWE 等） | **否** | 明文可重放；与已有 Go 证据同源 |
| **Session 内轮间间隙** | 同轨迹的 `pre_gap` | **否** | 首轮为 0；后续为相对上一轮秒数 |
| **跨 Session 到达 / 交错** | 实验指定的到达过程 | **是（显式）** | 原数据无全局时钟；合成并写明参数 |
| **时间量级对照** | TraceLab（可选） | 仅参考 | 不嫁接正文；用于扫参区间与叙事 |
| **产品边界** | 百炼 Coder（可选） | 对照 | 短会话 / 跨 Session 浅前缀收益低 → 不 overclaim |

**一句话：**  
真的东西（前缀、`pre_gap`）绝不假造；未知的东西（多 Session 何时叠在一起）用 **可控、可扫参、可复现** 的到达过程补上——这比假装「抽到了生产全局时间线」更干净。

## 3. 对现有数据的判定（已知事实）

### 3.1 `experiments/vllm_kv_cache/lmcache_traces/`（主资产）

字段：`session_id` · `model` · `input` · `output_length` · `pre_gap`

- **已知：** 每个 Session 内 turn 顺序与 `pre_gap`  
- **未知：** Session 何时开始、相对其他 Session 如何到达  
- **含义：** 「每条会话自己的时间轴完整；多条会话怎么叠在一起未知」

`pre_gap` 量级（全表粗统计）：中位约亚秒～1s 级，尾部可到数百～上千秒；首轮恒为 0。  
→ Session 内重放应 **尊重 `pre_gap`**，不要连发抹平空档。

### 3.2 TraceLab 公开包（`third_party/TraceLab/`）

- 有 round / request / tool·user 间隙，**无明文 prompt**  
- 适合：coding agent 时间形态标定、敏感性区间  
- **不适合：** 单独作为 Serving 正文负载

### 3.3 百炼 Coder 等

- 生产短会话为主；跨 Session「Family 浅头」按 token 计收益不高  
- 用途：边界图，不是主表

### 3.4 暂不做

- SWE-chat：门禁，暂搁置  
- 纯 hash 进主 Serving 证据  
- 为时间去上线真工具执行（`--tool-call-parser` + 真 Bash）——时间用 `pre_gap` / sleep 即可

## 4. 推荐构造管线

```text
1) 选 Session 集合 S（如 swebench__* 子集，或固定 Astropy/Django + 干扰 Entry）
2) 每条 Session：按 turn 顺序重放 input；turn i 相对 i-1 等待 pre_gap[i]
3) Session 启动：用到达过程 A(λ) 或固定错位 Δ 决定各 Session 的 t_start
4) 并发强度调到 KV 近满 / 出现淘汰（应力目标写进实验配置）
5) 对照臂：默认 LRU vs 保留策略；可选「抹平 pre_gap 连发」作消融
```

### 4.1 现在要做的事：模拟「业务像、早期可复现」的并发

当前缺口不是正文，而是 **怎么把多条 Session 叠在同一条实验时间轴上**。  
约束两条（同等重要）：

1. **符合业务场景**：长程 coding agent；轮间有空档（用真 `pre_gap`）；多 Entry 争用同一块 KV——不是聊天刷屏、不是单条独享 GPU。  
2. **实验早期可复现**：同一配置重跑，请求顺序与相对时刻一致；方便 diff LRU vs 保留、方便排障。

因此：**早期默认用确定性交错；随机到达只作后期压力扫参。**

### 4.2 业务像：并发里必须保留什么

| 必须像 | 怎么保证 |
|---|---|
| Agent 多轮前缀累加 | 重放真实 `input` messages，不截断成单轮 |
| 轮间空档（工具/思考） | Session 内严格 `sleep(pre_gap)`，禁止默认连发 |
| 多租户抢 cache | ≥2 条（通常更多）Session 时间重叠，直到出现淘汰 |
| 入口 / Family 可识别 | 每条轨迹带稳定 `session_id` → `open_session` / `session_params` |

| 早期可以不像 | 原因 |
|---|---|
| 生产级 Session 到达率曲线 | 无全局时间戳；强行拟合不可复现且难辩 |
| 在线真执行工具 | 增加非确定性；时间已由 `pre_gap` 编码 |
| 与 TraceLab 逐条间隙对齐 | 跨源嫁接；早期用分位数对照即可 |

### 4.3 可复现：早期默认到达方案 = 固定错位

**默认（冒烟 / 机制回归）：固定错位 Δ**

```text
给定有序列表 S = [s0, s1, …, s_{N-1}]   # 写死在配置里，禁止「每次随机抽 Session」
t_start(s_i) = i * Δ
Session s_i 内部：turn_0 在 t_start 发出；
                  turn_k 在 turn_{k-1} 返回后等待 pre_gap[k] 再发
```

- **复现钥匙：** `{S 列表, Δ, pre_gap 是否放大, 模型/mem-fraction, 种子占位}`  
- **调压力：** 只调 `N` 和 `Δ`（Δ 越小越交织、越容易打满）  
- **调业务空档：** 默认 `pre_gap` 原样；需要时用全局系数 `gap_scale`（仍确定性）

**后续（压力曲线）：泊松到达 + 固定种子**

```text
inter_arrival ~ Exp(λ)，rng = SeededRNG(seed)
t_start 由前缀和唯一确定 → 同一 seed 可复现
```

- 用于回答「随负载强度变化，收益是否单调 / 是否崩」  
- **不替代**固定错位作为第一张主表；错位跑通后再开泊松扫参

**可选补充：批启动**

- `t=0` 同时拉起 N 条，再各自走 `pre_gap`  
- 最快打满；更「应力」，不如固定错位贴近「陆续有人开 Session」

### 4.4 早期推荐实验矩阵（先小后大）

| 配置名（建议） | Session 集合 | 到达 | 间隙 | 目的 |
|---|---|---|---|---|
| `single_session` | 1 条目标 Session | — | 原始 `pre_gap` | 基线：无竞争 |
| `staggered_4sessions` | 固定 2–4 条 | 错位 Δ | 原始 `pre_gap` | **第一张并发表**：可复现竞争 |
| （调参） | 增大 N 或减小 Δ | 错位 Δ | 原始 `pre_gap` | 找到「开始淘汰」的工作点 |
| `staggered_4sessions_zero_gap` | 同并发集合 | 同 | 抹平 `pre_gap` | 消融：间隙是否关键 |
| （后续） | 同集合或扩大 | 泊松 λ + seed | 原始 `pre_gap` | 强度扫参 |

落盘目录：`experiments/sglang_kv_cache/staggered_native_replay/`。

配置示例：

```yaml
session_ids: [swebench__astropy__..., swebench__django__..., ...]  # 有序、写死
arrival: { type: staggered, delta_s: 2.0 }   # 早期默认
# arrival: { type: poisson, lambda_per_s: 0.2, seed: 42 }  # 后续扫参
gap_scale: 1.0
ablate_zero_gap: false
```

### 4.5 主表建议对照（与上表一致）

| 配置 | 目的 |
|---|---|
| 低并发 / 单 Session | 无压力：保留 ≈ LRU（不伤好情况） |
| 中高并发 + **原始 `pre_gap`** + **固定错位** | 早期主证据（可复现） |
| （可选）泊松 + seed | 后期强度曲线 |
| （可选）`pre_gap` × `gap_scale` | 敏感性；不当地面真值 |
| （可选）`pre_gap=0` 连发 | 消融：证明「间隙」是差异来源之一 |

### 4.6 TraceLab 怎么用

- 用其 tool / user 间隙分位数，检查 `gap_scale` 是否落在「coding agent 常见量级」  
- **禁止**：把 TraceLab 的间隙逐条嫁接到无关明文上却宣传为「真实同源负载」

## 5. 合格标准（构造完怎么验收）

负载 / 重放器算合格，当且仅当能支撑：

1. **无压力：** 策略与 LRU 接近  
2. **有压力 + 有间隙：** 保留策略在 TTFT / 重复 prefill / 目标 Session 命中上可分出差异  
3. **成本闸：** 保留跨度 / sidecar 有上限（接 docs/41、docs/42 GC）  
4. **可复现：** 固定种子 + 固定 Session 列表 + 固定到达参数 → 可重跑

---

## 6. 对外怎么说（避免被质疑）

**推荐表述：**

> 内容与 Session 内到达间隙来自真实 agent 轨迹；  
> 跨 Session 交错由显式到达过程合成，用于在受控条件下制造 KV 竞争。

**避免表述：**

> 完整复现了某条生产集群的全局到达过程。  
> （我们没有这条全局时间线。）
