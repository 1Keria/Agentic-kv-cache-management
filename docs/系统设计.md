# KV 续上概率：系统设计

打分器可替换（MLP、GBM、树网络等），控制器只消费同一份 `{p_i(H_k)}`。各档如何合成 `π`、`λ`、排序与破并列见 [`控制器.md`](控制器.md)。具体网络、特征和训练日志放在各自目录，第一版见 [`models/MLP/progress.md`](../models/MLP/progress.md)。

## 1. 模型和控制器怎么分工

控制器不是网络。一次驱逐里，控制器先开场、模型打分、控制器再收场。水位不进模型；模型不输出驱逐顺序。

工作顺序（cache 不够、必须腾页时）：

```text
1. 控制器：这次要腾多少页；水位、容量是多少
2. 控制器：硬规则先筛
     已经在跑、或等待队列马上要用的前缀 → 锁住
     仍留在树上（模型当结构看），但不进可驱逐候选
     若可驱逐叶子为空：不调用模型；新请求继续等。
     正在 decode 自己都不够：抢占/收回部分在跑请求，而不是扔锁住的前缀
3. 模型：对剩下的可驱逐叶子打分
     输入 = 整棵 radix tree + session/调度旁路（不含水位）
     输出 = 每个可驱逐叶子 i 一组概率
            p_i(H_k) ∈ (0,1),  k = 1..K
            = P(从现在起 H_k 内，节点 i 会被任意请求 prefix match)
4. 控制器：合成计价概率 π，再计价（规则见控制器文档）
     NetValue_i = (π_i − λ) × KVSize_i
5. 控制器：按 NetValue 从低到高扔，扔够这次要的页数就停
```

**模型**只回答「这段前缀在固定时间窗 `H_k` 里还会不会被任意请求 match」。

- **叶子之间、同一叶子随状态变**：有的短窗就会回来，有的只有更长窗才有机会，有的各档都接近 0。这表现在一组 `{p_i(H_k)}` 上，由树和 session 状态决定。
- **坑紧不紧变**：占用已经决定「现在必须扔」。如何由全部 `{p_i(H_k)}` 合成 `π`、`λ` 取多少，由控制器日内固定规则决定，不把占用乘进 `λ`、也不按占用只留最短窗。详见 [`控制器.md`](控制器.md)。尺子在变，不是预报占用期。
- **分档边界本身**：当日固定。每天用上一天的「下一次 match 隔了多久」重新统计定档，并重新拟合模型；日内不改 `H_k`、不按钟点改边界。在线学习以后再加。

**控制器**管三件事：何时驱逐、哪些绝对不能扔、扔到多少停。`λ` 和 `π` 的合成规则见 [`控制器.md`](控制器.md)。

交界是 `{p_i(H_k)}`。换打分器不改第 1、2、4、5 步。

模型前向的时机和现在 LRU 调 `evict()` 相同：**allocator 发现空闲页不够、必须腾空间的那一次。** 打完分交给第 4–5 步。训练更新不在这次 `evict()` 里做。

若关键路径太重，可以把 `p` 缓存在节点上，在 insert / 请求结束时刷新，驱逐时只读缓存；那是实现，不改「只在要腾页时才需要一份分」。

## 2. 模型要估计的量

一次前向对**当前所有可驱逐叶子**给出：在事先定好的几档时间窗里，会不会再被 prefix match。不读取水位和容量，也不输出秒，更不输出占用期：

```text
H_k 当日固定（每天用上一天的复用间隔分布重统计），日内不预测、不临场生成

p_i(H_k) = P(T_i < H_k)
         = P(从现在起 H_k 内，节点 i 会被任意请求 prefix match)
```

没有时间轴的二元「会不会用」没有定义；时间轴来自这些固定分档，不是来自控制器预报占用期。这也不是 `E[T]` 或 `E[log T]`：不把工具还要跑几秒当成回归目标。

「任意请求」包括同一 session 的下一跳，也包括别的 session 打到这段公共前缀。监督用日志里真实的下一次 match 时刻，只看它落不落在该档 `H_k` 内：

```text
y_i(H_k) = 1  若存在 t_next_match(i) 且 t_next_match - t_now < H_k
y_i(H_k) = 0  否则（含观测结束仍未见，按窗外处理）
```

标签不依赖当时 cache 有多满。结构上可分的是档，不是秒：

- 还活着、上一跳停在 tool-wait 的 frontier：短窗内几乎为 1。工具还要跑几秒进不了模型。
- 已经 `end_turn` / session 结束的私有尾巴：各档几乎为 0。
- 很热的公共主干：即使本 session 结束，短窗内仍可能为 1（别人命中，不是工具时间）。

`H_k` 取当天所用的复用间隔分档（由上一天分布重统计，让两类叶子能分开）。不取某个产品的工具 P50/P99，也不取实验总时长。可以 `K=1`，只定一档。控制器如何合成计价概率 `π` 见 [`控制器.md`](控制器.md)。这不是预测下次再挤的时刻。

## 3. 输入：整棵 Radix Tree + 树上没有的旁路信息

源输入是请求正文（`messages`、system、tool 名称）。那不进模型。

方法对象是 **当时 cache 里的整棵 radix tree**，再附上树里没有的 session / 调度信息：

```text
{p_i(H_k)}_{i ∈ evictable leaves} = f(whole radix tree, extra)
```

整棵树当输入，是为了留下对手的结构，而不是把占用收成「活 session 数、其余 token 合计」。对面是一条同样贵的 Agent 长树，还是一堆短 request 尾巴，局部路径看不见，几个标量也还原不出来。各打分器可以扁平化、做消息传递或只读局部，但监督对象仍是整棵树当时的状态。

输入分成两块，都不读正文，也都不读容量和水位。

**第一块：整棵 radix tree**

每个节点只带树里能直接读到的量：本段 token、root 到此的路径 token 与深度、reuse 次数、分叉数、是否叶子 / 是否可驱逐。边只有 radix 的父子边。不把文本、租户、产品名写进节点。

**第二块：旁路信息** `extra`

只保留**即使有了整棵树也读不出来、且用来估窗内会不会 match 而不是资源定价**的量：所属 session 是否未结束、是否携带工具、是否为存活的 Agent session（`session_alive` / `has_tools` / `is_alive_agent_session` / `stop_end_turn`）、已跑几跳、上一跳返回到现在的 `gap_ms`。`is_alive_agent_session` 是类别与生命周期的组合量，不代表模型真实 stop reason；`gap_ms` 用来判断这条 session 还像不像活着，不是让模型去拟合剩余工具时间。等待队列要点哪些节点是确定未来，只供控制器硬保留，不进打分器。

水位、容量 `C`、周转量 `ΔG`、这次要腾多少页 **不进 extra**。它们是控制器的资源状态；如何用见 [`控制器.md`](控制器.md)。

## 4. 标签怎么造（与打分器无关）

日志里没有 radix 快照。用请求序列（可匹配前缀、`session_id`、时间、`stop_reason`）离线按时间重放 prefix 插入。每来一个请求、match/insert 之后，对当时每个可驱逐叶子记一条：

```text
当时的树状态 + extra
T_i = t_next_match(i) - t_now     # 后面第一次有请求 prefix 覆盖到 i
      若当天结束仍未见 → 截尾
```

各打分器自己从「树状态 + extra」抽出输入。标签只由 `T_i` 与当日 `H_k` 决定：

```text
y_i(H_k) = 1[ T_i < H_k ]          # 截尾且窗尚未结束 → 该档为 0
```

标签不依赖当时用的是 LRU 还是别的策略，避免自己打自己。水位不写进样本输入。

`H_k` 用 D-1 的非截尾 `T_i` 分布定档，D 天只加载。切分按 session（或按时间）：同一条 session 的前后跳不能一边训一边验。评测 serving 用冻结负载重放，不要用训练集里的 session。

还没有 serving 闭环时，用已有 mix / 轨迹跑上述模拟器做冷启动。上线后改成每天用本集群 D-1 日志重统计 `H_k`、重拟合，D 天只加载权重。在线学习以后再加。

## 5. 通用性落在结构上，不落在某一天的权重上

会换场景仍应成立的是：

```text
H_k 和模型权重按日重统计、日内冻结，不是预测出来的占用期
模型只出 p(H_k)，不把水位学进窗内概率，也不回归工具秒数
控制器不是网络：用 λ 计价，按控制器文档合成 π、排序
队列已需要的前缀由控制器强制保留
还活着、尤其停在 tool-wait 的前缀，短窗概率高
已结束且没有共享命中的前缀，各档概率低，控制器可扔
```

不必跨天保持不变的，是某一天的权重和分档边界，以及某个负载下的 `λ`。跨场景仍应成立的是对象（整棵树）和分工（模型估窗内命中、控制器计价）。换打分器也不改这一条。

若几乎没有再次使用（全是单跳、没有共享前缀），各档 `p` 接近 0，控制器在高压下接近按大小驱逐。这是该有的行为，不是失效。

## 6. 当前边界

- 小模型估计的是当天分档 `H_k` 内会不会再被 prefix match，不限同一 session。
- `H_k` 与模型权重每天用上一天日志重新统计、重新拟合，日内冻结。在线学习以后再加。
- 整棵树进模型是为了结构，不是为了把占用定价学进网络，也不是为了回归墙钟。
- 方法对象是整棵 radix tree，不是局部子图。
- 打分器形态、`H_k` 的具体秒数由数据和按日重拟合决定。`λ`、`π` 合成、破并列以 [`控制器.md`](控制器.md) 为准。不改「模型估窗内命中、控制器计价、按日重拟合」这一条。
