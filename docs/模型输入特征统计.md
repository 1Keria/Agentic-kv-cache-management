# 模型输入原生字段清单

## 说明

本文只统计当前请求和 SGLang 运行时中直接存在的字段，不做特征加工，也不表示这些字段最终都会进入模型。



资源状态只供控制器使用，不进入“下一次命中时间”模型。

## 1. 客户端请求字段

来源：

`Engine/sglang/python/sglang/srt/entrypoints/openai/protocol.py`

### 请求内容

- `messages`：原始对话消息列表。
- `input_ids`：客户端直接提供的 prompt token 序列；提供后可跳过普通分词流程。
- `model`：请求指定的模型。
- `tools`：请求携带的完整工具定义。
- `tool_choice`：请求指定的工具选择方式。
- `parallel_tool_calls`：是否允许并行工具调用。
- `response_format`：请求的输出格式约束。
- `reasoning_effort`：请求指定的推理强度。
- `task`：请求指定的任务类型。
- `user`：客户端提供的用户标识。

### 生成参数

- `max_tokens`、`max_completion_tokens`：最大生成 token 数。
- `min_tokens`：最小生成 token 数。
- `n`：并行生成条数。
- `stop`、`stop_token_ids`、`stop_regex`：原始停止条件。
- `temperature`、`top_p`、`top_k`、`min_p`：采样参数。
- `frequency_penalty`、`presence_penalty`、`repetition_penalty`：重复和频率惩罚。
- `seed`：请求指定的随机种子。
- `ignore_eos`、`no_stop_trim`、`continue_final_message`：结束和续写控制。
- `stream`：是否使用流式返回。

### 缓存和调度字段

- `extra_key`：Radix cache 使用的额外键。
- `cache_salt`：请求提供的缓存隔离值。
- `lora_path`：请求使用的 LoRA。
- `priority`：请求优先级。
- `session_params`：客户端提供的 SGLang Session 参数。
- `rid`：请求 ID。

### 多模态字段

- 请求中的图像、音频、视频内容。
- `max_dynamic_patch`、`min_dynamic_patch`、`use_audio_in_video`：多模态处理参数。

### 可用范围

这些字段在 API 收到请求时存在。`messages`、`tools` 等字段经过模板处理后不会原样保存在调度器的 `Req` 中；如果模型确实需要它们，必须在请求进入系统时保留原值。

## 2. 分词后的请求字段

来源：

`Engine/sglang/python/sglang/srt/managers/io_struct.py`

- `input_text`：送入分词流程的文本。
- `input_ids`：分词后的 prompt token 序列。
- `mm_inputs`：分词和预处理后的多模态输入。
- `sampling_params`：请求的完整采样参数对象。
- `session_params`：SGLang Session 参数。
- `extra_key`：Radix cache 的额外键。
- `routing_key`：请求路由键。
- `priority`：请求优先级。
- `stream`：是否流式输出。
- `time_stats`：请求在 API 和分词阶段记录的原始时间字段。

## 3. 调度器中的请求字段

来源：

`Engine/sglang/python/sglang/srt/managers/schedule_batch.py`

### 输入和输出

- `rid`：请求 ID。
- `origin_input_ids`：进入调度器的完整输入 token 序列。
- `origin_input_ids_unpadded`：多模态 padding 前的输入 token 序列。
- `output_ids`：当前已经生成的 token 序列。
- `full_untruncated_fill_ids`：未截断的输入与输出序列。
- `fill_len`：当前已经填充的序列位置。
- `input_embeds`：请求直接携带的输入 embedding。
- `multimodal_inputs`：调度器保存的多模态输入。
- `sampling_params`：请求的采样参数对象。

### 请求身份和调度

- `session`：请求关联的原生 SGLang Session 对象；普通请求可能为 `None`。
- `extra_key`：缓存额外键。
- `lora_id`：LoRA 标识。
- `routing_key`：路由键。
- `priority`：调度优先级。

### 推理状态

- `require_reasoning`：请求是否启用 reasoning。
- `_is_reasoning_over`：reasoning 阶段是否结束。
- `reasoning_tokens`：已经生成的 reasoning token 数。
- `finished_reason`：请求的原生结束原因对象。
- `finished_len`：触发结束时的输出位置。
- `to_finish`：等待应用的终止原因。

### Prefix cache 状态

- `prefix_indices`：当前请求命中的设备 KV 索引。
- `last_node`：设备 Radix tree 的最后命中节点。
- `last_host_node`：Host cache 的最后命中节点。
- `best_match_node`：当前最佳匹配节点。
- `host_hit_length`：Host cache 命中长度。
- `swa_host_hit_length`：SWA Host cache 命中长度。
- `mamba_host_hit_length`：Mamba Host cache 命中长度。
- `num_matched_prefix_tokens`：调度器保存的前缀命中 token 数。
- `storage_hit_length`：存储层命中长度。
- `cache_protected_len`：已经插入并受保护的前缀长度。
- `cached_tokens`：请求累计记录的缓存 token 数。
- `cached_tokens_device`、`cached_tokens_host`、`cached_tokens_storage`：各缓存层记录的 token 数。
- `kv_committed_len`：已经提交的 KV 长度。
- `kv_allocated_len`：已经分配的 KV 长度。
- `swa_evicted_seqlen`：已经提前释放 SWA KV 的序列位置。
- `extend_input_len`：当前 prefill 需要处理的 token 数。

## 4. 请求时间字段

来源：

`Engine/sglang/python/sglang/srt/observability/req_time_stats.py`

### API 侧原始时间

- `created_time`：API 创建请求的时刻。
- `tokenize_finish_time`：分词完成时刻。
- `api_server_dispatch_time`：API 开始发送请求的时刻。
- `api_server_dispatch_finish_time`：API 完成发送的时刻。
- `first_token_time`：首 token 返回时刻。
- `last_time`：最近一次输出时刻。
- `finished_time`：请求完成时刻。
- `response_sent_to_client_time`：响应发送给客户端的时刻。

### 调度器侧原始时间

- `scheduler_recv_time`：调度器收到请求的时刻。
- `wait_queue_entry_time`：请求进入等待队列的时刻。
- `forward_entry_time`：请求进入执行阶段的时刻。
- `prefill_finished_time`：prefill 完成时刻。
- `completion_time`：调度器确认请求完成的时刻。

这里只保留原始时间戳。`age`、`gap`、排队时间、TTFT 和 E2E 都是由时间戳相减得到的量，不属于本清单的原生字段。

## 5. 原生 SGLang Session 字段

来源：

`Engine/sglang/python/sglang/srt/session/session_controller.py`

- `session_id`：原生 Session ID。
- `capacity_of_str_len`：Session 保存字符串的容量。
- `streaming`：Session 是否流式工作。
- `timeout`：Session 超时设置。
- `last_active_time`：Session 最近一次活动时刻。
- `req_nodes`：Session 保存的请求节点。
- `close_on_finish`：请求完成后是否关闭 Session。
- `_inflight`：Session 当前是否有请求在执行。

注意：

- 这些字段只在使用 SGLang 原生 Session 功能时存在。
- 普通 OpenAI Chat 请求不一定关联该 Session。
- 当前 `evict()` 不会收到 Session 或 Req 对象，因此驱逐时不能直接读取这些字段。

## 6. Radix Tree 节点字段

### 两种 Radix Tree 共同字段

来源：

- `Engine/sglang/python/sglang/srt/mem_cache/radix_cache.py`
- `Engine/sglang/python/sglang/srt/mem_cache/swa_radix_cache.py`

- `children`：当前节点的子节点集合。
- `parent`：当前节点的父节点。
- `key`：当前节点保存的 `RadixKey`。
  - `key.token_ids`：该节点保存的原始 token 序列。
  - `key.extra_key`：该前缀所属的缓存额外键。
  - `key.is_bigram`：当前 key 是否使用 bigram 表示。
- `value`：当前节点对应的设备 KV 索引。
- `last_access_time`：节点保存的最近访问值。
- `hit_count`：节点保存的命中计数。
- `host_value`：节点对应的 Host KV 索引。
- `hash_value`：节点保存的页 hash。
- `id`：运行时节点 ID。

注意：经典 Radix Tree 的 `last_access_time` 是单调时钟；SWA Radix Tree 的同名字段是递增序号，真正的 LRU 顺序由链表保存，两者不能混用。

### 经典 Radix Tree 独有字段

- `lock_ref`：节点锁引用计数。
- `creation_time`：节点创建时刻。
- `host_ref_counter`：Host KV 保护计数。
- `write_through_pending_id`：等待写穿完成的 ID。
- `priority`：节点保存的请求优先级。

### SWA Radix Tree 独有字段

- `swa_tombstone`：该节点的 SWA KV 是否已经释放。
- `full_lock_ref`：Full KV 锁引用计数。
- `swa_lock_ref`：SWA KV 锁引用计数。
- `prev`、`next`：Full LRU 链表指针。
- `swa_prev`、`swa_next`：SWA LRU 链表指针。
- `swa_uuid`：SWA 锁窗口标识。

## 7. 原生资源字段

这些字段来自缓存、调度器和内存分配器。它们只供控制器决定何时驱逐、哪些节点可驱逐以及需要释放多少页，不进入下一次命中时间模型。

- `num_tokens`、`swa_num_tokens`：本次需要释放的 Full/SWA token 数。
- `size`：KV 池容量。
- `page_size`：KV 页大小。
- `available_size()`：当前可用容量。
- `full_available_size()`、`swa_available_size()`：Full/SWA 当前可用容量。
- `full_evictable_size_`、`swa_evictable_size_`：Full/SWA 当前可驱逐数量。
- `full_protected_size_`、`swa_protected_size_`：Full/SWA 当前受保护数量。
- `sliding_window_size`：SWA 窗口大小。
- `waiting_queue`：调度器等待队列。
- `running_batch`、`cur_batch`：正在运行和当前处理的 batch。

## 8. 明确排除的非原生或派生特征

以下字段不进入这份原生字段清单：

### 当前项目注入的字段

- `custom_params.session_id`
- `custom_params.turn_idx`
- `custom_params.traffic_class`
- `custom_params.has_tools`
- `mlp_last_session_id`
- `mlp_pi`
- `mlp_net_value`
- `mlp_prefix_depth`
- `reuse_strength`
- `reuse_count`

- `reuse_value_density`

其中 `custom_params` 本身是请求扩展容器，但上述具体键是当前实验脚本注入的，不是 OpenAI 或 SGLang 的固定原生语义。

### 由原生字段计算的特征

- `node_tokens`、`path_tokens`
- `prefix_depth`
- `n_children`、`n_siblings`
- `is_leaf`、`is_evictable`
- `is_public_trunk`
- `session_alive`
- `is_alive_agent_session`
- `stop_end_turn`
- `has_tools`
- `age_seconds`、`gap_seconds`

- `prompt_tokens`、`completion_tokens`
- TTFT、E2E、排队时间
- 所有 `log_*` 特征

这些量以后可以作为“如何表示原始字段”的独立实验，但不能被称为系统直接提供的原生输入。

## 9. 驱逐时实际可直接读取的范围

当前 `evict()` 只收到需要释放的数量，不会收到 Req、Session、waiting queue 或 running batch。

驱逐时可以直接读取：

- Radix Tree 节点字段。
- Radix Tree 的锁、LRU 链表和墓碑状态。
- 缓存与内存分配器的资源字段。

驱逐时不能直接读取：

- 客户端原始请求。
- 调度器 Req。
- 原生 SGLang Session。
- 请求完成原因和请求时间字段。

如果以后确定需要请求或 Session 字段，应在请求到达、命中、插入或完成时保存字段原值，不应先转换成 `session_alive`、流量类别等人工标签。

## 10. 使用注意

- `rid`、`session_id`、节点 `id`、KV 索引、hash 和链表指针虽然是原生字段，但主要用于身份、关联和结构维护，不适合直接当连续数值输入。
- `lock_ref`、墓碑和资源容量属于驱逐合法性或资源约束，不代表节点未来是否会再次命中。
- `messages`、`tools`、token 序列和树结构都是变长输入；如果使用，模型结构必须直接处理序列或图结构，不能先把它们改写成人工业务标签。
- 本文只是原生字段清单。最终输入由后续消融实验决定。
