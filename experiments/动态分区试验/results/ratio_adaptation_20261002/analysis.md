# 直接调整缓存比例：淘汰反馈验证（2026-10-02）

## 实现

动态模式现在直接修改 Agent/普通请求的容量比例，Full 和 SWA 使用同一个比例。控制器只看已经发生的区域淘汰：

```text
agent_pressure   = agent_evicted_tokens / agent_quota
request_pressure = request_evicted_tokens / request_quota
gap              = agent_pressure - request_pressure
ratio_step       = clip(alpha * gap, -max_ratio_step, max_ratio_step)
```

比例更新受到上下限、压力滞回和 token 冷却约束。滞回只抑制更新而不丢弃小事件；比例已经到达边界时，继续把比例推向边界外的反馈会被丢弃，反向压力仍可立即积累。两类 Full/SWA 池不分别调参。

默认动态参数为 `normalized_pressure`、`max_ratio_step=0.05`、`pressure_hysteresis=0.02`、`cooldown_evicted_tokens=4096`；raw `eviction_share` 仍可显式指定作为历史对照。`agent_max_ratio=0.8` 同时提供普通区至少 20% 的容量保障，控制器统计中的 `request_min_ratio` 用于审计这条边界。

## 结果

| 场景 | 总体命中率 | Agent 命中率 | 普通命中率 | 额外重算 token | 比例轨迹 |
|---|---:|---:|---:|---:|---|
| 基线：固定比例 0.61（132 请求） | 89.019% | 89.133% | 77.456% | 298,955 | 固定 |
| 旧 raw eviction-share（132 请求） | 88.944% | 89.133% | 69.710% | 301,003 | 固定 |
| normalized-pressure，初始比例 0.61（132 请求） | 89.019% | 89.133% | 77.456% | 298,955 | 固定 |
| 固定比例 0.40（132 请求） | 88.304% | 88.411% | 77.456% | 318,411 | 固定 |
| 动态，初始比例 0.40（132 请求） | 88.944% | 89.133% | 69.710% | 301,003 | 0.430 → 0.800（15 次） |
| 固定比例 0.80（192 请求） | 77.728% | 89.133% | 0.000% | 688,562 | 固定 |

## 解释

1. 初始比例 0.61 的 132 请求 workload 中，normalized-pressure 与固定 0.61 完全相同（总体 89.019%、普通 77.456%）。这不是控制器失效，而是初始比例已经适合该 workload，且普通区没有产生足够的新压力；动态分区的收益必须在需求比例变化或初始比例失配时观察。旧 raw eviction-share 在同一 workload 将普通命中率降到 69.710%，说明只看绝对淘汰占比会过度偏向 Agent。
2. 初始比例 0.40 的 Agent 压力场景中，动态比例在 15 次反馈内上升到 0.80。相对固定 0.40，总体命中率提高 0.639 个百分点，Agent 命中率提高 0.722 个百分点，额外重算 token 减少 17,408；普通命中率下降 7.746 个百分点，体现了容量比例的真实取舍。
3. 初始比例 0.80、普通请求密集的场景最能验证动态分区。固定 0.80 的普通命中率为 0%，动态旧边界处理为 53.197%；修复边界反馈累积后提高到 73.972%；采用 0.05 步长和 4096 token 冷却后提高到 84.262%。对应总体命中率分别为 77.728%、84.535%、87.193% 和 88.509%，Agent 命中率都为 89.133%。
4. 快反馈版本相对固定 0.80 少重算 333,312 token（约 48.4%），说明收益主要来自普通前缀被保住，而不是改变 Agent 区内部 LRU。比例轨迹在 Agent 压力阶段回升，在普通回访阶段快速回落，符合不依赖工具返回时间预测的设计目标。

## 结论和下一步

直接调整比例是有收益的，但收益来自流量阶段发生变化且固定初始比例失配的场景；在容量宽裕或固定比例已校准的场景，总体差距会很小。当前推荐把 normalized-pressure 作为动态模式默认控制器，使用同一比例映射 Full/SWA，并继续用普通回访首条命中、普通侧额外重算 token、比例轨迹作为主要指标。

下一步应在更多随机 seed、不同 Agent/普通流量阶段顺序和不同初始比例上做矩阵验证，再确定 `0.05/4096` 是否作为统一默认；不应把本报告中的单条 workload 数值直接当成普适收益。

实验脚本允许阶段阈值只记录不终止：`--allow-phase-requirement-failure`。本报告中的共享前缀 workload 均 `n_issued=n_ok`，阈值异常来自共享前缀的第一个 session 被淘汰，不能按服务错误解读。
