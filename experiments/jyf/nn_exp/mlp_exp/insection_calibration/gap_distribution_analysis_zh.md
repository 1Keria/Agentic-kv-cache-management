# Prefix reuse gap 分布与来源分析

## 结论

`60s～3551s` 的 observed reuse gap 空洞来自原始请求时间戳的采集/回放形态，不是 MLP 数据构造脚本通过分桶、缩放或取整制造的。原始请求由密集 burst 构成，相邻 burst 约相隔一小时；同一 agent anchor 和同一 exact prefix 的请求，要么在一个 burst 内于 60 秒内再次出现，要么跨到下一 burst，最短约 3551 秒后再出现。

构造脚本会让每个请求包含的多个 message-boundary prefix 分别形成样本，因此会重复同一个请求对之间的时间差、放大双峰的样本数量，但不会改变 gap 数值。

## 构造脚本做了什么

1. 直接解析原始 `start_time` 为 Unix timestamp。
2. 对相同 rolling exact-prefix hash 保存上次出现时刻 `last_t`。
3. 下一次出现时直接计算 `gap = current_t - last_t`。
4. 不对 gap 做 scale、round、clip 或人工插入空档。
5. 对日志中最后一次出现且后续没有 reuse 的 prefix，设置 censor duration 为 `dataset_end - last_t`。

因此，构造逻辑不会生成 60～3551 秒空洞。它的放大作用来自一个请求包含多个 message-boundary prefix：同一次 agent 请求返回会同时让多个历史 prefix 得到相同或相近的 gap 标签。

## 对实验的影响

- `age=60s` 后、未来小于约 3491 秒的窗口中没有 observed positive event，无法验证短中期 calibration。
- 这些位置 ECE 很低只是因为实际风险为零，不能用来证明模型准确。
- `[60,180)`, `[180,600)`, `[600,1800)` 三个模型 bucket 没有 observed event 支撑，主要受 censored survival loss 和跨 bucket 约束影响。
- 当前 wall-clock trace 更像定时 burst replay，而不是连续自然到达流量；结论不能直接外推到生产流量。

## KM 在条件风险中的使用

Kaplan–Meier 首先估计生存函数：

`S(t) = P(T > t)`。

累计 reuse 风险/累计事件概率是其补集：

`F(t) = P(T <= t) = 1 - S(t)`。

对于已经等待 age=a 的节点，未来 h 内 reuse 的条件风险为：

`R(a,h) = P(a < T <= a+h | T > a) = 1 - S(a+h)/S(a)`。

实验中也可以先筛选 `T>a` 的 at-risk cohort，将残余时间定义为 `R=T-a`，再对残余时间运行 KM，得到 `1-S_residual(h)`；两种写法等价。右删失样本在 censor 时刻前保留在 risk set，之后退出，但不会被计作 reuse event。
