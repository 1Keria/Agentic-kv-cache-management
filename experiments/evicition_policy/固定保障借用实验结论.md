# 固定保障份额 + 空闲容量借用实验结论

实验日期：2026-09-30

本实验验证一种不改变 Agent/普通请求基础比例的区域策略：Agent 和普通请求各自保留固定保障份额；当一侧未使用自己的保障份额时，另一侧可以使用闲置容量；当所有容量被占用时，优先回收超过基础保障的借用部分。基础比例固定为 Agent 61%、普通请求 39%，Full/SWA 使用相同策略。

## 实验配置

- 模型：DeepSeek-V4-Flash
- 缓存策略：两组均为 LRU；仅区域管理策略不同
- 请求顺序：同一份离线 workload，固定到达顺序
- 请求数：1261/1261
- 输出上限：16 tokens
- gap scale：0.1
- Agent 分类：使用现有请求分类器
- fixed：固定 Agent 61% / 普通请求 39%
- borrow：固定保障 61% / 39%，允许空闲容量借用

两组正式运行都满足 `1261/1261` 请求成功、`0` 错误，prompt token 总数均为 `8,917,410`。因此命中率和缓存 token 可以直接比较。

## 持续混合 workload

| 策略 | 总体命中率 | Agent 命中率 | 普通请求命中率 | cached token | 墙钟秒 | 请求/s | TTFT p50 |
|---|---:|---:|---:|---:|---:|---:|---:|
| fixed | 87.9638% | 92.6560% | 37.7154% | 7,844,096 | 354.421 | 3.5579 | 632.9 ms |
| borrow | 87.6509% | 92.3892% | 36.9086% | 7,816,192 | 353.516 | 3.5670 | 606.7 ms |

相对 fixed，borrow 的总体命中率下降 0.3129 个百分点，缓存 token 少 27,904（约 -0.36%）；墙钟时间减少 0.26%，请求吞吐增加 0.26%。这组持续混合流量没有显示借用策略的缓存收益，整体可视为与 fixed 接近但略逊。

最终 Full/SWA 驱逐 token：

| 策略 | Full 驱逐 | SWA 驱逐 |
|---|---:|---:|
| fixed | 807,680 | 888,576 |
| borrow | 856,832 | 912,384 |

持续混合 workload 中 borrow 的借用空间主要被短时空闲区使用，但在两类请求同时持续到达时，借用回收增加了驱逐次数，未转化为命中率收益。

## 阶段切换 workload

阶段顺序为 `request_first -> agent_middle -> request_last`，同一 session 归属于固定阶段。结果如下：

| 策略 | 总体命中率 | Agent 命中率 | 普通请求命中率 | cached token | 墙钟秒 | 请求/s | TTFT p50 |
|---|---:|---:|---:|---:|---:|---:|---:|
| fixed | 84.6423% | 90.5655% | 21.2107% | 7,547,904 | 383.628 | 3.2870 | 644.6 ms |
| borrow | 88.0844% | 92.6968% | 38.6902% | 7,854,848 | 381.127 | 3.3086 | 618.7 ms |

相对 fixed，borrow 的总体命中率提高 3.4421 个百分点，缓存 token 增加 306,944（约 +4.07%），请求吞吐增加 0.66%，墙钟时间减少 0.65%。Agent 命中率提高 2.1313 个百分点，普通请求命中率提高 17.4785 个百分点。

分阶段缓存结果：

| 阶段 | fixed 命中率 | borrow 命中率 | 变化 |
|---|---:|---:|---:|
| request_first | 20.2124% | 43.2408% | +23.0284 个百分点 |
| agent_middle | 90.5655% | 92.6968% | +2.1313 个百分点 |
| request_last | 22.3693% | 33.4087% | +11.0394 个百分点 |

Full/SWA 驱逐 token：

| 策略 | Full 驱逐 | SWA 驱逐 |
|---|---:|---:|
| fixed | 1,124,864 | 1,222,912 |
| borrow | 877,824 | 877,824 |

borrow 相比 fixed 少驱逐 Full 247,040 token（-21.96%），少驱逐 SWA 345,088 token（-28.22%）。阶段切换时，一侧的闲置保障容量被另一侧复用，避免了固定分区在新阶段重新建立缓存时的容量浪费。

## 结论

1. **借用策略对阶段切换有效。** 当 workload 从普通请求切换到 Agent 请求、再切回普通请求时，固定保障份额不会随历史阶段自动转移；borrow 可以直接使用闲置容量，因此显著提高命中率并减少驱逐。
2. **借用策略不能替代动态比例控制。** 持续混合 workload 中两类请求长期同时活跃，几乎没有稳定的闲置份额，borrow 没有带来收益，且最终驱逐量略高。
3. **当前正式设计建议保留 borrow 作为区域管理的基础机制。** 它不依赖工具返回时间、turn 时长或 workload 预测，比例不变，行为容易解释；在阶段性负载下可以消除严格分区的明显损失。
4. **暂不把 borrow 宣称为所有 workload 的统一最优策略。** 持续混合结果表明，后续仍需研究借用回收顺序、最小保留时间或借用准入规则，避免频繁借用和立即回收造成额外驱逐。

## 实现边界

- 驱逐仍遵循 SGLang 当前叶节点粒度，申请回收的 token 数可能因叶节点大小而实际回收更多 token。
- `effective_capacity_tokens` 是当前区域在对方闲置时可使用的上限；两侧统计值分别包含对方闲置容量，因此不能将两侧有效容量简单相加当作物理容量。
- 本实验没有改变 LRU 的节点选择规则，也没有引入工具时间或 turn 返回时间预测。

## 后续实验建议

下一轮应固定 borrow 机制，针对持续混合 workload 单独扫描基础比例和借用回收策略。优先比较：

- 借用页的最小保留时间；
- 只回收借用部分且按 LRU 顺序回收；
- 当两侧同时超过保障份额时的回收优先级；
- Full/SWA 是否需要分别设置借用上限。

阶段切换 workload 的结果已经足以支持保留“固定保障 + 空闲容量借用”作为动态分区的第一版设计；上述扩展用于解决持续混合场景中的边际损失。
