# 有限准入保留 v2 验证

日期：2026-10-09。范围：纯 Agent 请求、官方 UnifiedRadixCache CPU 索引重放；未运行模型计算、GPU 时延或混合流量。

## 结论

v2 的“有限准入与保留”规则在中等缩容阶段有效，但没有解决四分之一容量下的极端缩容问题。

规则只改变保护资格准入：当新边界与已有保护边界共享依赖、且共同依赖超出保护预算时，拒绝新资格并保留旧资格；新边界仍可正常计算和进入原生缓存。只有原生压力回收或依赖释放时，才沿用 v1 的撤销和 LRU 回退。策略不使用 session、时间、工具调用或未来访问预测。

## 实验与审计

冻结的 20 个会话、1,206 个请求按相同轮询顺序执行。比较 LRU、冻结 v1、v2 三种变体，每种执行恒定容量和 `C0 → C0/2 → C0/4 → C0` 两条轨迹，共 **7,236 个请求**。每个条件都在同一个缓存实例内完成，预算切换之间不清空缓存。

v1 和 LRU 的请求级命中、Full 驻留匹配、历史匹配及真实释放量均与上一轮冻结结果完全一致。v2 的 41 项测试、预算履行、锁、物理页所有权和事件序列审计通过。

## 资格生命周期证据

v2 在恒定容量中只准入 130 个单元，拒绝 899 个新边界和 177 个连续扩展；其中 128 个单元在保护期间被再次观察到复用，复用事件 299 次。v1 则准入 1,206 个单元，只有 189 次保护期间复用，未复用资格周转明显更快。

在缩容轨迹中，v2 准入 518 个单元，拒绝 652 个新边界和 36 个连续扩展；其中 193 个单元被复用，复用事件 220 次。半容量时 v2 平均保留 7.83 个单元，v1 为 7.44 个；四分之一容量两者都约为 2.54 个，和命中结果一致。

这些数据支持“限制新资格轮换”这个机制判断，但仍是单条固定轨迹上的观测，不能解释每个 victim 的完整反事实收益。

## 最终判断与下一步

这版优化值得保留：它在中等容量变化下显著减少资格轮换，缩容恢复全程相对 v1 提升 6.56 个百分点。但不能宣称已经解决动态分区适配，因为四分之一容量没有收益，恢复阶段还出现相对 v1 的滞后。

下一步应转向**容量感知的边界粒度选择**：在极端缩容前，只保留真实 Full/SWA 依赖完整、成本较低的浅边界，并记录其被替代边界的后续损失。这个方向需要先用合法候选和实际依赖做离线筛选，不能通过元数据制造 checkpoint，也不能直接引入固定比例。

当前不建议立即做 GPU v2 论文结果：先验证浅边界粒度策略能否在四分之一容量阶段超过 LRU 和 v2；若不能，应把论文主张收窄为“有限保护资格轮换在中等动态容量下的收益”。
