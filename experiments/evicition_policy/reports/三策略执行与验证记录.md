## 冻结输入与控制变量

- GPU 验证：20 个完整 calibration 会话 / 894 请求，仅 LRU；不抵扣评估中的 LRU。
- 评估：同一份 20 个完整 evaluation 会话 / 1,206 请求，LRU → LFU → SLRU 各一次，无额外重复。
- 两个集合均按 `SHA256("formal-schedule-proposal-v1:42:" + session_id)` 排序后取前 20 个完整会话。原 90 秒启动间隔统一乘 0.30，变为 27 秒；会话内每个源等待也乘 0.30。源等待与有效等待同时逐请求保存，属于合成加速流量，不冒充原始线上时间。
- 保留全部请求、历史输入、源输出长度及源等待字段，不拼本地输出进下一轮，不执行工具，不接入分类器或业务分区。仅修改回放时钟，不修改 token 内容、请求顺序或输出目标。
- 候选 Full 容量 524,288、SWA 比 0.1；容量随会话数同比缩小 20%，实际容量逐 rank 验证并绑定校准签名。TP8、最多 8 个运行请求、页 256、chunked prefill 8,192、seed 42、原生后端及其他参数相同。
- 模型为只读引用的 DeepSeek-V4-Flash；隔离官方 SGLang 0.5.13.post1。启动前复核 wheel、全部官方安装文件、依赖锁、模型元数据及分片清单；不声称已逐字节复核所有权重。
- decode CUDA Graph 开启；prefill 图按官方兼容规则禁用，不强制绕过。Full 按所选原生策略回收；SWA 独立回收仍是 LRU，不称全池同策略。
- 每策略目标约 1 小时，安全上限 2 小时，单请求仍为 30 分钟；触发则失败保留证据，不将截断结果算成功。三次目标约 3 小时，启动、预热、重启和尾部排空另计。

## 相同预热与干净起点

每次启动独立服务，先做原有 4 请求编码/流式协议核验，然后跑两遍相同的 12 个工程形状：校准输入长度 p50 / p95 / 最大值各一条、172,032-token 合成长输入一条、8 个固定校准任务首轮并发一组。

长输入只由校准最长输入在末 256 token 之前插入重复的校准内容得到，专用于工程形状验证，不是真实轨迹，不计测量成绩。工程形状每条输出 128 token，不改变校准或评估的原始输出目标。验证服务回显的输入 token、输出数及长度结束标志；并发请求数不等于已证明 scheduler 的实际 batch 形状。不能宣称覆盖了全部内核编译形状。

每遍形状前、正式测量前均 flush 并通过原生指标确认空缓存。每种策略结束后停止本实验自有服务进程组，核对 GPU 分配释放，再启动下一种；不清理无关用户进程。

## 预注册验证条件

以下阈值在密度验证前写入 `criteria.json`，是工程准入标准，不是业务 SLO 或策略收益目标：

| 检查 | 放行条件 |
|---|---|
| 完整性 | 20 会话 / 894 请求全部完成，输入/输出哈希和长度、等待、缓存起点、进程释放通过 |
| 撤回 | 原生字段全覆盖且总数为 0 |
| 队列观测 | 8 个 TP rank 各自的前后直方图计数均覆盖 894 请求，不累加 rank |
| 队列耗时 | 加速压力下每 rank 均值 ≤10 秒、p95 所在桶上界 ≤60 秒 |
| 采样队列深度 | 最大值 ≤24；超过说明约 1 小时目标由过载排队换取，不放行 |
| 客户端到达误差 | p99 ≤1 秒，无缺失/非有限值 |
| 原生回收活动 | 单调原生回收 counter 的观测窗口原始增量至少 1,000,000；只作同环境压力门禁，不解释为 Full 单池逻辑 token |
| 缓存压力 | Full 驻留率采样 p95 ≥0.95，SWA 驻留率采样 p95 ≥0.90，避免时间压缩后没有可观察压力 |
| 验证时长 | 完整 894 请求不超过 75 分钟；超时失败，不截请求 |
| 池计量与监测 | Full/SWA 采样守恒，无缺失计量或 monitor 错误 |
| 工程预热 | 两遍各 12 请求完成，包含 172,032-token 形状 |

通过后生成带哈希的 `release.json`，绑定服务配置、评估清单、协议/形状预热、验证证据和全部实验脚本。三种策略启动前分别再次核对；运行期间不得修改 `scripts/*.py`、`scripts/*.sh`，否则安全拒绝继续。失败不隐式降低标准、不自动增加重复、不带病进入下一策略。

## 验收和解释边界

每种策略必须完成 1,206 次请求且容量/后端/图配置签名一致，才进行描述性对照。保存命中率、TTFT/请求耗时、排队直方图、池驻留、撤回、生成续接和失败证据。单次差异不证明稳定领先或统计显著，结论范围仅限冻结的 20 会话样本。

逐请求 `queue_time` 已知因官方序列化丢时间戳而不可信，保留原值但不用于排队结论。原生回收 counter 可能混合 Full/SWA 和 TP 聚合，不能除以 8 伪装单池逻辑 token。缺少完整淘汰事件/合法候选覆盖，不能把未命中全算作错误淘汰，也不能仅凭回收计数证明 Full 策略持续承压。历史采集器精确版本及 provider 模板仍未知，这些限制不会因实验成功而消失。

下一步建议只保留 LRU 与 SLRU，至少执行一组 `LRU → SLRU` 和一组 `SLRU → LRU` 的顺序平衡重复，保持同一 workload、容量、启动密度和预热流程，以估计运行波动并检验本轮 0.4785 个百分点命中率差异是否可重复。LFU 和 TLRU 暂不进入下一轮主矩阵；详细失效归因另用事件诊断批次完成。
