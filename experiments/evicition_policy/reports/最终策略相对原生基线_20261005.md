# 最终动态分区策略相对原生基线

## 结论

在同一份 227 请求混合 workload、同一模型和同一 KV 容量下，最终候选策略

```text
elastic 动态分区
+ 20%/20% 最低保障
+ 共享弹性容量
+ 1024-token borrowed 尾部分段
+ Ghost 真实重算保护
```

相对完全原生 unified（不分区、原生 LRU）取得了 **+14.0485 个百分点的总体命中率**，Agent 命中率提高 **+14.1406 个百分点**。普通请求命中率保持不变；按 shadow 统计的额外重算 token 减少 **25.52%**。

这是同一回放的一次成对正式对照，不能把它解释成跨 workload 的普遍保证。历史上 1024-token + Ghost 的三次候选复核总体命中率为 `54.6959% ± 0.439 pp`；这些旧复核的服务端 prompt token 统计口径与本次成对回放不同，因此没有与本次数字混合计算。

## 时间阶段拆分

服务端阶段已按 `metrics_after.prom - metrics_before.prom` 重新统计，结果见[阶段拆分明细](../../动态分区试验/results/fair_unified_vs_final_20261005/stage_breakdown.md)和[机器可读结果](../../动态分区试验/results/fair_unified_vs_final_20261005/stage_breakdown.json)。这一步去除了启动探测和预热请求；服务端阶段总量以 TP rank 0 为主，客户端指标仍是 227 个请求的逐请求统计。

8 个 TP rank 的各阶段事件计数完全一致；由于各 rank 的本地计时存在异步观测差异，表中不跨 rank 平均，而是固定使用 rank 0，并在机器结果中保留各 rank 的范围。

| 阶段 | Unified | Elastic | 变化 |
|---|---:|---:|---:|
| 排队累计 | 79.041 s（346.67 ms/阶段事件） | 73.897 s（324.11 ms/阶段事件） | −5.143 s |
| `prefill_forward` 累计 | 320.068 s（1,403.81 ms/阶段事件） | 318.228 s（1,395.74 ms/阶段事件） | −1.839 s |
| 服务端 TTFT | 433.332 s（1,908.95 ms/请求） | 435.670 s（1,919.25 ms/请求） | +2.339 s |
| 服务端 E2E | 953.477 s（4,200.34 ms/请求） | 901.195 s（3,970.02 ms/请求） | −52.281 s |
| 首 token 后 ITL | 520.108 s（152.75 ms/token） | 465.488 s（136.71 ms/token） | −54.620 s |

这里的 `TTFT` 包含请求创建到首 token 的排队、prefill、首个 decode 路径及其他开销，并不等于纯 prefill。Elastic 的 `prefill_forward` 只下降约 0.58%，而首 token 后的 ITL 观测值累计下降约 10.50%。两种策略的 decode 算法和 kernel 没有改变，因此这不能解释为 decode 本身被优化；它更可能反映缓存命中差异改变了 prefill 与 decode 的交错、调度等待和输出间隔。`E2E - TTFT` 与 ITL 累计只相差约 37 ms（两种策略均如此），说明后续输出阶段的拆分是自洽的，但不等于纯 decode 计算时间。

TTFT 减去排队与 `prefill_forward` 的残差为 Unified 34.223 s、Elastic 43.545 s，不能直接解释为 HTTP 或 tokenizer 时间，因为阶段事件比完成请求多 1 次，且服务端没有完整的 HTTP wall-time/tokenizer elapsed 指标。客户端 TTFT 与服务端 TTFT 的差值分别为 36.883 ms 和 42.180 ms；tokenizer CPU 增量分别为 22.170 s 和 22.060 s，说明 tokenizer 不是两种策略时间差的主要来源。

## 结果解释

1. 收益主要来自 Agent 区。普通请求的命中率两边完全相同，说明这次 workload 中策略没有以牺牲普通请求缓存为代价换取 Agent 命中。
2. 命中率提升与 shadow 额外重算下降方向一致：原生 unified 多产生约 451 万个因缓存丢失而需要重新处理的 token，最终策略减少到约 336 万个。
3. TTFT p50/p90 和墙钟均下降，但 TTFT 均值基本持平并略高 0.8%。因此当前证据支持“减少缓存重算”，对平均 TTFT 的改善仍应在更多重复和更长 workload 上复核。
4. 最终 elastic 回放结束时 Agent Full/SWA 驱逐量分别为 `2,061,312 / 3,710,208` token；请求侧为 `3,584 / 6,656` token。unified 不启用区域统计，不能从同一接口得到按区域驱逐量。

## Shadow 统计边界

Shadow 是按相同输入编码构造的、无限保留历史 page 前缀的影子索引，额外重算定义为 `max(0, h_inf - h_actual)`。混合回放没有生成 token id，所以它只近似完整运行时前缀；本次 coverage gap 为 unified 4,864 token、elastic 5,632 token，相关限制已保留在原始 [`shadow_recompute.md`](../../动态分区试验/results/fair_unified_vs_final_20261005/shadow_recompute.md) 中。
