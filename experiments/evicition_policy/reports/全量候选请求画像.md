日期：2026-09-26。这是所有已准备候选的离线内容统计，**没有选择正式实验规模，也不是缓存收益测量**。

## 1. 统计口径

- 数据：去重后的 SkillsBench / OpenHands × DeepSeek-V4-Flash with-skills，共 108 条会话、58 个任务、5,348 次调用。
- 编码：官方 SGLang 0.5.13.post1 的目标服务编码，thinking=true、reasoning_effort=max；与源 provider 模板不同的可能性保留。
- 输入 token 为本次目标编码长度；输出 token 为原始 usage 记录的长度目标，不是本次生成观测。
- 保留全部候选，无成功率、前缀复用率或策略收益筛选。上游发布者已有健康轨迹筛选，不能称无筛选线上流量。
- 原始数据、规范化文件、编码文件和画像通过哈希关联；CSV 明细可复查，不含请求文本。

## 4. 前缀内容结构

以目标输入 token 的完整 256-token 页为单位，使用“之前完整前缀哈希 + 当前页内容”构成标识；不将上下文不同但页内容相同的片段合并。

- 全量有 35,040 个不同的完整上下文前缀页标识。
- 其中 12 个页标识被多个会话引用。
- 所有会话分别去重后的页引用数合计 36,324；单页最多被 108 个会话引用。

这里不含每条输入不足一页的尾部，也不含本地生成输出；不恢复跨会话真实时间顺序。它仅描述内容共享，**不是 Full/SWA 物理槽位数量，不是无限缓存严格命中上界，也不是实时可驱逐集合**。

## 5. 对后续设计的直接约束

1. 不能直接拿当前 131,072 Full token 的烟测容量跑全量：已有输入超过此值；正式时应按完整会话逐一准入并重新校准，而非截短输入。
2. 长等待必须保留。单会话累计等待可达约 72.1 分钟，所以完整回放无法保证每轮都在一小时内结束。
3. 跨会话启动密度会改变竞争；它必须显式冻结为合成调度，不把任务原始绝对时间拼成线上流量。
4. 可在完整校准会话上先找有淘汰但无失控排队的压力点，再冻结评估规模；不根据 LFU/SLRU 的收益挑数据或容量。
5. GPU 协议烟测的 2 会话 × 前 2 轮只是工程测试，与正式规模选择无关。
