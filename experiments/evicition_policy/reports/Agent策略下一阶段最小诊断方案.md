# Agent 策略下一阶段：从尾部选择到沿链回收的最小诊断

状态：**已实施。最终实测与机制判断见 [Agent 候选前沿实测诊断结论](Agent候选前沿实测诊断结论.md)。本文件保留为实施前方案和验收口径。**

依据：[前缀重复需求统计](Agent前缀重复需求与候选可观测性统计.md)、[修订后的日志深挖](Agent定制淘汰策略日志深挖.md)、现有 `scripts/replay_agent.py` 与 `configs/agent_policy_diagnostics_schema.json`。

## 1. 本阶段只做一个决策

确定后续机制应优先解决哪一个问题：

1. 回收开始时，多条链的新尾部之间选择不当；
2. 删除尾部后，回收继续深入刚暴露的旧前缀，损失集中在这个阶段；
3. 节点释放粒度、活跃锁定或 Full/SWA 约束主导损失，优先改排序的依据不足。

累计复用门槛、二次机会、父链信用均保留为待验证候选，不预先选为主机制。事件发生在哪个阶段只是损失归属，不自动证明该次淘汰可避免。

## 2. 先解决回放内容一致性

现有回放等待本轮实际完成，但下一轮继续提交冻结的历史输入。输入链具有高重复性，不代表本轮生成内容也进入下一轮。因此继续重复原来的长实验，不能补上生成尾部价值的证据。

### 2.1 结构微实验：精确续接，先验证采集

建议从 **2–4 个会话、每会话 4–8 轮**的受控场景起步；这是拟定规模，不是已验证运行配置。下一轮直接用 token ID 构造：

```text
I[t+1] = I[t] + O[t] + 固定的追加内容 token
```

- `O[t]` 必须是这一轮实际返回的完整 `output_ids`，不能用历史回复替换。
- 不经过“转回文本、重新套聊天模板、重新分词”的流程；逐轮断言 `I[t+1]` 以前一轮 `I[t] + O[t]` 为精确前缀。
- 追加内容模拟工具返回或下一步上下文，明确标为合成内容；不声称真实执行了工具或原任务。
- 另外记录实际提交到 KV 的 token 边界、页对齐范围与 namespace。内容续接断言通过，不等于全部输出 token 已具有驻留 KV。
- 受控历史改写的用例显式记录预期分叉边界，不要求它通过严格追加断言。

至少覆盖三个行为：持续追加；一条链停止续接而其他链继续；一次受控历史改写/分叉。场景中的未来安排只作离线验收标签，不传给原生策略，也不能把一次请求完成或最后一个 trace 请求当作服务可见的任务结束。

微实验先只用原生 LRU，目的为校验事件链。先在无 Full 容量压力的点核对匹配和写入，再在发生回收的点检查候选及祖先暴露。实际预算、模型、页大小、Full/SWA 容量须通过预检后冻结；少量会话是否足以触发 Full 回收目前未知，不能预先保证。SWA 窗口内在释放应与容量淘汰分开解释。

### 2.2 后续两个阶段的边界

| 阶段 | 固定内容 | 能回答的问题 |
|---|---|---|
| 结构微实验 | 续接规则、初始内容、追加内容、场景安排 | 采集是否完整，新尾部如何出现，删叶如何暴露祖先 |
| 固定逻辑 trace 的策略重放 | 输入/输出 token、外生请求逻辑操作顺序、初始状态与容量 | 相同需求条件下，不同淘汰选择造成什么差异 |
| 内容一致的闭环 serving | 初始任务/内容、模型与工具规则、初始到达过程 | 策略改变完成时间和后续交错后，实际收益是否仍存在 |

各策略自行生成内容，即使 temperature 为零，也不能未经核对就当成完全相同 trace。把一次生成结果冻结为后续输入，却继续允许测量运行生成不同输出，会再次引入当前问题。

固定重放必须让各策略重新执行匹配、分配、锁定、节点分裂与回收。不能把 LRU 的 victim、实际匹配长度、瞬时节点 ID 或分配量作为另一个策略的固定输入。完整重放之后的缓存状态允许分化；只有单次决策反事实才要求相同初始候选状态。是否采用原生缓存对象的 CPU 重放，或另行支持固定输出的引擎路径，在第一阶段采集验收后再决定。

## 3. 增加只读的逐次回收采集

这是对当前“原生策略、不加观测补丁”阶段的**下一阶段边界变更提案**：恢复本实验锁定的官方引擎，在独立诊断副本中增加可关闭的只读采集，记录补丁与原始源码哈希；淘汰选择、排序规则、锁定规则保持原生。现有项目引擎和旧结果不作覆盖。

单纯开启已有 KV 事件不能先假定足够；需逐项确认其是否覆盖完整候选、锁、split 和父节点暴露。缺失项才考虑补充。实现尚未完成，本方案不声称已有可运行入口。

### 3.1 每次回收必须能重建全过程

```text
回收开始：哪个池、需要释放多少、完整初始合法候选
  第 1 步：实际 victim、释放量、由此新暴露的父节点
  第 2 步：更新后的候选、实际 victim、释放量、再次暴露
  ...
回收结束：总释放量、超额释放量、剩余压力或失败原因
```

最小记录：

| 记录对象 | 必须包含 |
|---|---|
| 回收事件 | 单调 `eviction_id`、池、触发原因、目标释放量、初始候选、完成状态 |
| 每一步 | `step_seq`、候选增删、选中 victim、策略实际排序键、释放页/字节、父节点暴露与原因 |
| 节点/页身份 | namespace、完整前缀身份、当前节点区间、临时节点 ID、split 映射；节点不等于固定页 |
| 复用证据 | 产生/首次存储请求、不同后续请求的真实 demand、最近 demand；原生 `hit_count` 单独保存 |
| 生命周期与驻留 | store、committed 边界、lock/unlock、evict、flush、取消与抢占等相关事件 |
| 池与并行性 | Full/SWA 独立标记、TP rank/缓存实例、逻辑去重依据；物理字节明确 per-rank 或聚合口径 |

不能把首次插入、chunked prefill 或同请求内重复探测计为独立回访。结构性 split 的计数继承，与给新 token 赋信用必须区分。

### 3.2 候选分类用多个独立维度

“新尾部、暴露祖先、复用叶子”并非天然互斥：一个旧节点可能在删子节点后才暴露，且已有复用；一个压缩节点可能含有新旧两类页。至少分别记录：

- **进入本次候选的方式**：回收开始即合法，还是删除哪个子节点后新暴露；
- **内容来源**：输入增长、生成输出、旧前缀、分叉或未知；
- **复用状态**：尚无后续不同请求 demand，或已发生 demand；
- **回收位置**：该节点在本轮回收开始时相对原驻留末端的位置，以及沿同一路径已删除多少 token/字节。

报告初始候选的唯一空间占比，以及逐步新暴露候选的占比，分母分开。不要把同一候选在每一步反复出现累计成更多物理空间。

只读采集使用缓冲写出，不能为了拿统计调用会更新热度或匹配状态的函数。初始完整快照加精确增删记录可以代替每一步重复输出全量集合；缺事件、乱序、丢包或缓冲溢出都要让该窗口验收失败。日志开销可能影响调度，需保留关闭/开启采集的开销对照。

## 4. 第一轮实际统计的三个输出

1. **候选结构表**：每次回收初始候选中，尚无后续 demand 的内容有多少；旧祖先在哪一步暴露；同时给节点数、逻辑页数和可验证物理空间。
2. **回收深度—后续需求/重算表**：分别统计初始末端回收和后续暴露祖先回收释放的空间、之后被重新需要的内容及成本；同时保留剩余前缀深度、实际匹配长度和请求级额外处理量。
3. **逐次时间线**：完整候选 → victim → 父节点暴露 → 是否继续向同一条链回收 → 后续真实需求。优先同时保留正向、反向和三策略共同缺口窗口，不能只选有利案例。

历史轨迹窗口可帮助定位，但截取几轮直接从空缓存开始不能声称复现原时刻；需从一致初始状态重放必要前史，或有可验证完整状态恢复。结构微实验里人为制造的尾部占比不能外推为真实工作负载的分布。

### 4.1 损失归属的限制

- 只把已证明此前存储、后来删除且尚未重新存储的内容，关联到后续对应需求缺口；必要的新内容计算另计。
- 每个请求的缺失页/前缀损失只计一次，不能同时归给尾部与祖先；跨会话共享物理页也不能重复记空间。
- Full 与 SWA 可能共同限制一次前缀匹配，不能把两池缺口相加成为总重算；原因不足时记为联合或未知。
- 被删除内容后来被需要，只能证明发生了后续需求，不能证明该次选择比其他合法选择更差。
- 真正的策略净收益必须比较至少释放相同空间、满足逐步祖先依赖和锁约束的替代选择，并纳入替代 victim 的后续损失。
- 没有后续需求的窗口仍存在右删失，不自动视为无用；尤其不能用 trace 结束作为在线已知信号。

## 5. 验收后如何选机制

| 观察到的现象 | 下一步值得检验的改动 |
|---|---|
| 初始候选几乎全是新尾部，累计计数没有区分力 | 累计二次访问门槛降为基线；进一步检验链级近期进展、空间周转与单位保留成本是否有独立信息 |
| 后续损失集中在删尾后继续回收旧祖先 | 检验限制单次沿一条链深入、分散到其他合法路径的回收方式；必须计算被替换内容的损失 |
| 单个压缩节点造成大量超额释放 | 检查是否有合法的页级拆分/回收方式；不能假定直接拆分无成本或所有后端都支持 |
| SWA、活跃锁、抢占或回收失败占主导 | 先解决对应约束；不能把 Full 评分差异作为主要解释 |
| 候选存在明显近期复用差异，且反事实显示值得保留 | 再检验可衰减二次机会或有界信用；规模和参数由独立校准决定 |

以上均为待测方向。若强原生基线已接近可验证的合理选择，不必强行设计 Agent 内部新策略，可以把系统贡献集中于后续分类与动态分区。

## 6. 本阶段完成标准与实施次序

1. 恢复并核验隔离环境，确认目标缓存路径与日志插入位置；预算和模型尚待实际预检，旧运行配置不能当成当前可用资源的证明。
2. 实现精确 token 续接的诊断客户端和可关闭的只读事件采集；新模式单独命名，不改写旧回放语义或旧正式结果。
3. 用少量受控场景通过三项验收：精确续接成立；每次回收候选与父节点暴露可完整重建；后续缺口能够对接已证实的驻留/删除事件，不能对接的单列未知。
4. 原生 LRU 下完成低压力控制和一个可解释回收压力点；识别主导池。通过后才增加相同预算下的 SLRU 诊断。
5. 将输出收敛到上面的三张表/时间线，再决定采集内容一致的真实 Agent 轨迹、固定逻辑 trace 的重放方式，以及只改一个机制的对照实验。

新增原生策略比较仍需独立校准与评估，并报告工作负载、回放方式和采集开销。当前既有 20 会话只能作为探索证据，不能用于反复调参后宣称独立泛化收益。
