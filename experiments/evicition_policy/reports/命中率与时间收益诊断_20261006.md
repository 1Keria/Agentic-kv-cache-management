# 命中率与时间收益诊断（2026-10-06）

## 结论

当前结果没有推翻缓存命中应减少 prefill 的基本规律；它说明本实现的时间账本中加入了额外的缓存管理和调度成本。命中率只统计复用 token，端到端时间还要支付匹配、区域判断、Ghost 元数据、候选扫描、回收和批处理交错的成本。

串行回放是最直接的证据：Elastic 命中率提高约 0.6 个百分点，但 `prefill_forward`、服务端 TTFT 和 E2E 都变慢。开放环回放中 TTFT 下降，主要原因是排队累计时间大幅下降；同一批实验的 prefill 和 ITL 仍变慢，因此不能把 TTFT 改善归因于命中率。

Ghost 消融进一步定位了当前实现的主要问题：在相同 72 请求 workload 和动态分区配置下，关闭 Ghost 后 Elastic 的命中率只少约 0.15 个百分点，但 prefill、服务端 TTFT 和 E2E 均明显降低。下一步应先把 Ghost 从请求/回收热路径移出或改为低开销实现，再评价动态分区本身。

在这个消融中，关闭 Ghost 后命中率仅下降约 0.15 pp，但 prefill 下降约 9.98 s，服务端 TTFT 下降约 89.40 s，E2E 下降约 117.86 s，客户端平均 TTFT/E2E 也分别下降约 20.9%/14.6%。这是当前最强的定位证据。由于两个 run 是独立进程，数值应看作方向性证据；但差距远大于串行测量噪声，且阶段拆分方向一致。

## 为什么命中率没有直接变成时间收益

1. **命中率和时间统计的是不同对象。** `cached_tokens_total` 只表示请求前缀有多少 token 可直接复用。它没有扣除 Python 侧的前缀匹配、区域分类、借用重分类、候选扫描和 Ghost 计算。只有实际减少的 uncached prefill 工作才会降低 GPU 时间。
2. **收益量太小。** 串行和开放环 227 请求的命中率只提高 0.59–0.65 pp，相当于约 4.9–5.3 万个输入 token；而动态分区触发的回收次数增加 37–85%，Ghost 还对每次匹配和回收做 page 构造、逐 token rolling SHA-256、索引查询和候选评分。少量省下的 prefill 不能覆盖热路径开销。
3. **串行场景没有排队收益。** 227 请求串行回放中，Elastic queue 只增加 2.54 s，无法抵消 prefill 增加 60.68 s 及回收路径增加 282.21 s 的成本，所以 TTFT/E2E 直接变差。
4. **开放环的 TTFT 受排队主导。** 固定到达时刻下，策略改变每一轮批次的组成和完成顺序。Elastic 的 queue 可以减少数千秒，但 prefill 和 ITL 同时增加；因此 TTFT 下降并不证明缓存路径更快。
5. **ITL 不是纯 decode kernel 时间。** 它包含首 token 后的调度等待、批处理交错和输出传递。当前 run 中 Elastic 的 ITL 累计在串行、开放环 227、compact 72 请求分别增加 6.97 s、296.50 s、136.47 s。decode 算法没有被优化，批次结构变化足以让 ITL 变差。
6. **Full/SWA 的合并命中率掩盖了池级差异。** 当前指标把 device cache 命中合并统计，而回收和调度分别作用于 Full、SWA 两套池。必须同时记录 Full/SWA 的命中、uncached prefill、回收时间和请求批次，才能判断某些命中是否真的减少了对应池的计算。

## 实现层面的直接证据

当前 Ghost 热路径位于 `Engine/sglang/python/sglang/srt/mem_cache/radix_cache.py:907` 和 `swa_radix_cache.py:677` 的 `match_prefix`，每次请求会构造 page 并调用 `request_region_ghost.observe_match`。`request_region_ghost.py:273` 对每个 page/token 重新计算 rolling SHA-256；回收时 `radix_cache.py:1104` 扫描候选并调用 Ghost 分数，`radix_cache.py:1588` 又沿节点父链构造完整前缀并写入 Ghost。Full 和 SWA 都走同类逻辑。

## 下一步

- 时间性能基线先使用 `elastic + Ghost 关闭`，单独把 Ghost 当作命中/重算保护消融；在 Ghost 未优化前，不把它作为默认线上策略。
- 给 `match_prefix`、Ghost hash/lookup/score、区域重分类和 `evict` 增加独立计时，避免用总 eviction 时间猜测开销来源。
- Ghost 改为节点插入或首次回收时预计算并缓存 page 指纹，匹配时只查表；避免每个请求逐 token SHA-256 和每次回收重复走完整父链。
- 后续正式比较同时报告命中率、uncached prefill token、prefill_forward、queue、ITL、E2E 及 Full/SWA 分项，且对串行和开放环分开解释。

## 数据与边界

阶段报告由 `analyze_stage_metrics.py` 对每个 run 的 `metrics_after.prom - metrics_before.prom` 重新生成，rank 0 用于正文，8 个 TP rank 的阶段事件计数一致。串行、开放环 227 请求和 compact 72 请求的客户端回放均为 227/227、227/227、72/72 成功。开放环固定到达时间会改变排队结构；Ghost 消融是独立进程的一次对照，不能当作统计显著性结论。
