## 2. 核对口径

- **原文事实**：标明指定版本与章节；不把综述、搜索摘要或此前回答当作实验设置证据。
- **资产事实**：以官方发布页、仓库及数据卡为准；表内规模是论文口径或页面口径，不冒充本地全量统计。
- **适配判断**：本报告针对“纯 Agent、原生淘汰策略、不训练模型、不分区、V4-Flash 服务回放”的研究目标作出。
- **未确认**：未找到作者公开轨迹直链、下载失败或许可未逐项核对时明确写出；“未验证”不等于“确定没有公开”。
- **时间字段**：请求开始到下次开始、响应完成到下次请求、工具执行耗时是三种不同量，不能互换。
- **版本范围**：以下按用户列出的具体 arXiv 版本与 UniCache 作者 PDF 阅读，不宣称已经比较了所有历史/后续版本。

### 3.2 逐篇思想及适配边界

**Continuum / Continnum。** 指定 HTML 使用 Continnum 拼写，资产名为 continuum。核心是按工具历史和保留成本确定 KV 的存活期限，并结合程序级调度。论文采集了各 100 条 SWE-bench、BFCL 轨迹，采集模型为 GPT-5；后续服务回放不等于用该模型重新运行工具。BFCL 负载还有缩放，不能照搬成未经处理的真实请求。[P1]

本项目借鉴：把缓存回收后的重算、加载、排队分别记录，观察长工具等待的尾部。本轮不复现 TTL 或改变调度；论文的组合收益不能当作单独淘汰排序收益。官方仓库 README 明示当前预览实现未包含论文中的估计模块，不能把它当完整论文复现。轨迹文件仍需核验，而不是看到“开源代码”就宣称“轨迹已拿到”。[A1]

**PBKV。** 预测未来多步 Agent 调用，先处理已结束工作流的缓存，再综合不同活跃工作流对共享节点的需求，并保守预取。它使用具体任务与框架的组合，而非单纯重放题目；工作流结束消息等信息也有客户端可见性前提。[P2]

本项目借鉴：按公共前缀/私有历史、已明确结束/仍活跃分别统计；记录缓存压力和运行阶段。不训练它的预测器，也不把“文件读完”当作服务当时已知的结束消息。若获取不了作者 trace，只能称“使用相同基础题库另行采集”，不能称原样复现实验。

**KVFlow。** 用 Agent Step Graph 表示执行关系，按距离未来调用的步数管理缓存并预取。指定版本不只有随机 token 微基准：还使用 PEER 的 Financial QA 输入进行四角色模拟；不过这些也不应称为自然线上到达轨迹。[P3]

本项目借鉴：固定可共享前缀、动态后缀、输出长度和并发的微型场景，快速证明原生策略确实生效。不得把显式工作流图/未来步数加入本轮原生策略。当前官方仓库还包含 ScaleSim，需锁定对应文件和提交，不能将全部目录视作论文 v1 的精确资产。[A2]

**CacheScout。** 从前缀识别可重复的 Agent 上下文，在线学习执行转移，指导保留与预取；不依赖预定义图或离线训练。论文四个题库都经过相同多 Agent 框架，原始 GSM8K 或 MT-Bench 并不因此天然成为 Agent 请求。[P4]

本项目借鉴：增加“角色固定前缀/会话历史”的复用分解；不要因为自己也不要求预定义工作流就认为避开了此类已有工作。未来比较要注明在线学习、会话关联与前缀可识别性的前提；本轮仅借鉴画像。

**UniCache。** 以不同复用机制组织队列、分别排序并适应性调整队列权重。其数据构造将内容与时间模型组合；因此不应将全部时间戳说成真实采集。它分析的 ALFRED、CC-Bench 是本次最直接的数据线索。[P5]

本项目借鉴：先做分组复用统计，再决定是否需要不同机制；CPU 分析需和 GPU 对照验证。公开模拟器使用 vLLM 控制路径，不能当作当前 SGLang/V4-Flash 双池行为的等价实现，也不应复制其改过的引擎进入原生基线。[A3]

**SAECache。** 将块按语义/复用模式入队，结合续接判断与在线反馈调整保留优先级。它的主要服务结果来自三类聊天数据；CC-Bench 主要出现在间隔分析。论文讨论了命中提升却未获得更好 TTFT 的情况，不能只依靠摘要概括效果。[P6]

本项目借鉴：记录淘汰后再次需求、策略开销以及命中到延迟的转化。不要假定模型输出或推理内容永不复用——本项目要检查它们是否进入下一轮精确前缀。本轮不接入其小模型、队列或在线参数学习。

## 5. 两个尤其不能照抄的实验假设

### 5.1 “轮间隔”不等于“工具等待”

UniCache §6.1 将内容数据与采样的时间结合，Agent 间隔参数从 CC-Bench 拟合；SAECache 附录 E 则有自己的过滤和拟合口径，两者并非同一套无处理时间数据。[P5][P6]

本项目应采用：

- 有请求开始、响应完成、下一请求开始时，直接计算完成后等待。
- 只有两次请求/消息的开始时间时，保留其原名，不能拿它作 sleep 再加一次推理耗时。
- 只有内容时，标注“合成节奏”。不要把 CC-Bench 的分布直接命名为 ALFRED 的真实工具延迟。
- 不强制套用对数正态：先报告经验分位数、长尾、缺失与截尾，再决定是否用分布模型做敏感性分析。

### 5.2 同是 Agent，复用来源也可能完全不同

编码 Agent 的累积历史、具身环境的观察/动作、多角色工作流反复使用的角色提示，是不同来源。CacheScout 强调固定角色上下文，UniCache 的部分数据强调会话内续接；这些不应被理解为普适且互斥的结论。[P4][P5]

因此我们建议分别测量：同会话历史、同角色跨会话前缀、跨角色公共前缀、新增尾部，以及上下文压缩/重写。不能为了让某种策略显著获益，额外加统一长 system prompt、人工制造角色标签或重复复制会话。

## 6. 可借鉴的方法：本轮做什么，后续才做什么

下表是基于原文的本项目设计建议，不是已验证收益。

| 来源 | 本轮可直接吸收的分析/实验方法 | 后续机制方向及限制 |
|---|---|---|
| Continuum | 同时统计等待、排队与重算；看完整会话而不只看单请求 | 保留期限须计机会成本；不在原生基线中 pin KV 或改程序调度 |
| PBKV | 对结束/活跃、共享/私有历史分层；记录负载阶段 | 有明确结束信号才讨论生命周期回收；预测与预取是后续单独变量 |
| KVFlow | 微基准控制固定前缀、动态增长、输出长度、并发 | 需要图可见性；图驱动对照应另设组，不给原生策略透传未来 |
| CacheScout | 统计角色固定前缀份额、角色切换及跨会话共享 | “不离线训练”不等于无预测；后续创新需与在线转移方法区分 |
| UniCache | 分复用类型画像；区分逻辑工作集与物理容量；验证模拟器偏差 | 多队列是已有方向；迁移模拟器需核 SGLang 双池、节点分裂和锁 |
| SAECache | 同时报命中、额外重算、TTFT、决策开销及负收益场景 | 语义权重和反馈学习留到以后；不能预设输出/思考一律优先淘汰 |

本轮最有价值的不是一次实现六种策略，而是为原生 LRU/LFU/SLRU/TLRU 建立可解释的数据与观测。论文报告的 speedup 受模型、框架、offload、调度和工作负载共同影响，不能直接贴在本项目的策略排名表里。

## 7. 建议的可执行数据落地顺序

### 第一步：只做少量样本审计，不急着全量拼接

1. 固定 CC-Bench、AgentBank 与 SkillsBench 的数据集 revision；每个候选先取少量不同任务/来源模型样本，检查结构与许可证，不执行记录中的工具命令。
2. CC-Bench 检查 `trajectory` 的 JSON 编码、父子链、真实请求/响应边界、人工输入、工具返回、旁支和压缩；无法重建的字段保留未知。
3. AgentBank 先选 `alfred`，确认观察—动作轮次，保留原始格式及转换记录；不声称有原始工具耗时。
4. SkillsBench 优先恢复原先 V4-Flash/OpenHands 文件，比较其 API 请求保真程度；不把历史 manifest 中的 910 当作当前实际文件数。
5. 跟进 Continuum 官方 artifacts：若找到 trace，核对内容、时序、缩放和许可；未找到就列为待获取，不占用主流程等待。

### 第二步：按证据能力分成三组，不按品牌合并

| 组 | 入组要求 | 可得结论 |
|---|---|---|
| 自然等待主组 | 已有 Agent 执行；完整请求内容、依赖和可验证的完成后等待 | 本数据下工具/编排暂停与缓存失效关系 |
| 内容泛化组 | Agent 轨迹完整，但缺自然等待或只能用统一模板重建 | 前缀结构、增长、内容复用；合成节奏下的压力敏感性 |
| 机制微基准组 | 受控合成请求与依赖 | 原生策略是否生效、某种结构下的机制差异 |

CC-Bench 不保证直接进入第一组，AgentBank 默认进入第二组；最终按字段审计决定。尚未通过审计时，不提前替换 README 已规划的主工作负载。

### 第三步：分别建基线，再考虑纯 Agent 内部混合

- 第一份主 workload 仍从保真程度最高的轨迹来源选择；不会为了同时覆盖六篇论文而强行扩大规模。
- 对 CC-Bench、OpenHands、ALFRED 分别给出原生策略结果；同一任务不同模型运行、重复下载副本按任务级分组，防止校准/评估泄漏。
- 若再混合多个 Agent 来源，单独冻结组合规则，报告会话数、请求数、输入 token、唯一前缀量和等待分布，不仅报告调用比例。
- 重新 tokenizer 化时记录源模型与目标 V4-Flash 差异；源模型 token 数和源模型生成耗时不能冒充本次服务观测。
- 下载和派生文件统一落到 `experiments/eviction_policy/data/`；数据文件不提交 Git，报告与来源清单可保留。需要账户同意或私有资产时先说明，不索取/落盘明文密钥。

建议后续每个数据版本产出 `source_manifest.json`、`schema_audit.json`、`filter_log.jsonl`、`session_statistics.json`；分别记录原始数量、重复数、保留数、排除原因、时间可信度和转换版本。
