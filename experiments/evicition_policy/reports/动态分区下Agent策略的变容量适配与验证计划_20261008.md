# 动态分区下 Agent 策略：变容量适配与验证计划

2026-10-08 冻结设计；2026-10-09 更新完成范围：运行中硬预算执行层与官方 CPU 缓存重放已实现，LRU/保护版本 × 恒定/收缩恢复共 4 组、4,824 请求完成，35 项验收检查通过。结果和机制启示见 [变容量验证与 Insight](变容量Agent缓存机制验证与Insight_20261009.md)。本轮仅验证 Agent-only、串行输入重放和外部固定预算；GPU 时延、混合流量共同后端、分区归属候选和借用归还组合尚未验证。以下保留原冻结设计与分阶段验收，不把全部计划项写成已完成。

## 研究目标的修订

Agent 区内部策略需要同时满足两个目标：在既定预算内保留有用前缀；在动态分区要求归还容量时，及时交还合法可回收空间，并在容量恢复后继续利用空间。因此，运行中改变同一个实例的逻辑预算应成为前置验收，而不只是最后的混合流量补充实验。

[v1 完整验证](可复用边界保护_v1完整验证_20261008.md)中，命中率提高 9.7113 个百分点、平均 TTFT 降低 18.73%，支持复用依赖保护在一个固定 Agent-only 压力点的价值。这些结果没有证明变容量适配。多个静态容量点之间重启服务也不能替代运行中收缩、扩张的验证。

容量变化本身不能证明传统策略或论文方法失效。LRU 本身可以在新增回收要求下继续选择候选。后续需要在同样的预算变化和归还要求下比较合规性、重算与延迟，记录新机制的退化和对另一类请求的影响。

## 设计冻结时核对的实现缺口

本节记录 2026-10-08 的设计起点。现已通过独立执行层补充运行中预算、保护裁剪与真实占用/释放记账；混合请求的归属和范围适配仍待完成，冻结的 v1 策略源码未改。具体完成项和接口限制以最新验证报告为准。

| 项目 | 当前事实 | 待补充内容 |
|---|---|---|
| 保护预算 | [v1 配置](../configs/bounded_frontier_v1.json)在初始化时读取最多 8 个单元、Full 262,144、SWA 4,096 token，之后没有预算通知接口 | 接受运行中的可执行预算更新；允许保护上限暂时为零 |
| 压力回退 | [实现](../scripts/bounded_frontier.py)在合法候选受保护阻挡时撤销最旧阻挡单元 | 接受分区回收范围与归还量，明确返回实际释放和未完成量 |
| 物理占用 | `trim_budget()`限制保护资格的依赖量，不限制 Agent 的全部驻留 KV | Agent 驻留量必须由分区层真实约束；仅修改保护上限不足以构成变容量实验 |

现有 Full/SWA 保护是一组依赖：连续 Full 祖先与末端必要 SWA 窗口。任一依赖失效会取消整个单元的保护资格。撤销资格并不要求两池同时物理删除，释放仍服从原生锁和合法候选。

## 最小适配规则

维持已有 LRU 顺序、统一保护单元和最旧单元撤销规则；只补充预算和回收契约，不增加返回时间预测、额外评分或第二个比例控制器。

1. **上层决定额度。** 分区层提供 Agent 当前可执行的 Full/SWA 预算、预算版本及回收范围。硬配额、最低保障、软边界和借用资格分别记录。对于此前的 elastic 候选，软线移动只改变回收优先级；不能把软线下降直接解释为必须马上删除全部超线 KV。
2. **更新保护资格。** 硬预算收缩时，同步裁剪保护限额，沿用既有绝对限额作为上限；反复撤销最旧单元，直到剩余依赖符合新限额。任一池放不下的单元都应让出资格，单元数可以低于 8。首版只解决正确适配，不声称这种裁剪已是最佳性能设置。
3. **履行真实归还。** 上层需要空间时，提供具体归还量及合法候选范围，包括仅回收借用层等约束。先按现有规则回收；保护阻挡归还时撤销阻挡单元，再继续 LRU。策略应报告实际释放量和未完成量，不能用取消保护的 token 数代替真实 free。
4. **保留锁约束。** 目标小于锁定占用或缺少合法叶候选时，记录尚未完成的回收，按调度器原有规则等待解锁后重试，避免忙循环。保护不能产生额外硬锁；现有请求的引用锁不能被配额更新绕过。
5. **正常扩张。** 扩张时允许后续实际插入的边界获得资格。已释放的 KV 必须按正常请求重新计算，不能仅因额度恢复就宣称依赖已经恢复。

Full/SWA 使用上述同一套规则，预算检查按物理池分别记账。共享祖先只计一次；如果物理叶回收连带释放另一池，按原生实际释放结果记账。共享前缀的类别归属沿用分区的既有规则，不通过修改缓存命名空间来制造互不共享的对照。

## 分阶段验证

### 先验证连续收缩和恢复

先用小规模、固定请求顺序的 Agent-only 场景，在同一个服务实例中注入逻辑预算变化。使用统一缩放因子把变化映射到 Full/SWA 的页对齐额度；物理总池保持不变，对 Agent 不可使用的剩余空间必须由预算执行层真实限制。

第一组采用“初始预算 → 一半 → 四分之一 → 初始预算”；另保留恒定预算控制。触发事件和请求内容在运行前冻结，不根据某策略的命中差挑选收缩时刻。事件编号只用于受控实验注入，不作为线上分区控制器的新规则。

LRU 和保护版本接受完全相同的逻辑预算、回收范围和请求顺序；各策略单次实验内部不中断服务、不清空缓存。先通过以下验收，再扩大规模：

- 预热后收缩和扩张，实际驻留量及释放量符合预算执行规则。
- 单个大保护单元也放不下，能够撤销资格并完成合法回收。
- 目标低于锁定占用，能够明确报告欠量，解锁后继续回收。
- Full 或 SWA 单独先成为限制，仍使用同一规则；覆盖共享祖先与分叉。
- 保护限额降至零、恢复正数后，状态正确且无死循环或虚假的依赖恢复。

### 再验证动态分区组合

在兼容的共同后端上冻结分区配置，先比较“同一动态分区 + LRU”与“同一动态分区 + 可撤销依赖保护”。先提供一致的分区层候选和回收接口；已有 ghost 借用保护与 v1 的相互作用应单独消融，避免同时启用后把效果全部归给 Agent 内部策略。

整体系统对照仍保留三种基础条件：完全原生无分区、固定分区、动态分区。先用相同内部策略识别分区本身的收益，再增加动态分区内的 Agent 策略对照，识别内部策略的独立贡献。分类器与其他共同设置保持一致。

真实反馈分区的额度轨迹可能随淘汰和性能改变，不要求两种策略产生同样的轨迹。上述外部固定预算对照用于隔离机制，最终混合流量对照用于验证整个系统；二者分别报告。

## 指标与证据

每次变化记录：预算版本及触发事件；旧、新硬预算与软边界；Agent 总驻留、锁定、可驱逐和受保护依赖量；请求归还量；两池真实释放；因预算或归还撤销的单元；未完成回收量及原因；解锁重试后的状态。

性能同时报告全程指标及每次收缩/恢复后的窗口指标：缓存命中、未命中输入、TTFT 均值/p95、请求耗时、回收耗时、恢复期间损失。存在符合相同插入时机、命名空间和匹配规则的历史影子索引时，再单独报告容量损失导致的额外重算；否则保留未命中输入或参照缺口的原名。

混合流量还需单独报告普通请求的命中与 TTFT，以及它等待 Agent 归还容量的时间，防止总体 token 加权收益掩盖另一类请求退化。归还完成时间必须结合当时合法候选与锁定量解释，不把物理上无法回收的部分算成保护算法拒绝交还。

第一步的验收结论应是“能够按预算变化运行，且保护不阻挡合法回收”；随后才能评价“在相同归还约束下留下了更有用的复用边界”。固定容量收益、变容量收益和完整动态分区收益分别保留，不能互相替代。
